The `pigen` CLI compiles one `.pigen` source through the structured pipeline (preprocess, lex, parse, semantic, RTL lowering, naming, output model, SV emission) via `pigen_compile_source`. Contract: silent success — the output file is written, stdout is empty, exit 0, no "wrote" notice; loud failure — a diagnostic with the native source span goes to stderr, the exit code is nonzero, and no output file is written (no partial output). Arguments: `pigen INPUT.pigen [-o OUTPUT.sv]`; without `-o` the output path is the input path with `.sv` substituted or appended. Argument errors print usage to stderr and exit 2. The structured frontend accepts the data-first declaration dialect (data type, then optional transfer annotation, then name, e.g. `logic [7:0] buf stage;`); transfer-first prototype spellings such as `buf [7:0] stage;` or `input buf [7:0] request` are diagnosed at the original span by design, not accepted — the existing tests/examples corpus is written in the prototype dialect and is migrated per subsystem (what/are/the/remaining/architecture/migration/gates.md). No validator bridge, fallback, second dialect or per-file choice.
