`pigen_build_output_model` walks the parsed syntax tree in source child order against the completed lowering and fills the ordered output model.

Interface: `int pigen_build_output_model(pigen_output_model *model, const pigen_syntax_tree *syntax, const pigen_rtl_lowering *lowering, pigen_output_error *error);` Returns 0 on success, -1 on error; a failure reports the diagnostic and stops — it may leave partial state and no test asserts a failed call left the model unchanged (how/should/compiler/builders/fail.md). The 4th argument `error` receives the diagnostic when one is reported and may be NULL (the walk still returns -1).

`pigen_output_error` (include/pigen/output.h): `typedef struct { pigen_source_span span; const char *message; } pigen_output_error;` — a span + a borrowed static message, no ownership; the string outlives it. `span` is the node's `location.source_span`; `message` is static; an unset diagnostic is all-zero. The NULL-argument path (NULL model/syntax/lowering returns -1) leaves `*error` unset: it zeroes it when non-NULL and never fills it there. The shape is on master; the missing-identity diagnostic's span-reporting and stop-on-error wiring into the walk is the next in-order step (what is the missing lowered identity diagnostic of the build walk).

`int pigen_output_error_is_set(const pigen_output_error *error)`: 1 when set (non-NULL message AND `span.start <= span.end`), 0 otherwise (NULL error, NULL message, or all-invalid span). It distinguishes a NULL-argument -1 (no diagnostic) from a real missing-identity diagnostic.

`const pigen_syntax_tree *syntax` (include/pigen/syntax.h): a `pigen_syntax_node` carries `parent`/`first_child`/`last_child`/`next_sibling` (source order) and `location.source_span` (the span an OPAQUE item holds); `PIGEN_SYNTAX_OPAQUE` nodes are trivia/separators. Walk from the `PIGEN_SYNTAX_COMPILATION_UNIT` root down each `first_child` → `next_sibling` chain.

`const pigen_rtl_lowering *lowering` (include/pigen/rtl_lower.h), after `pigen_lower_rtl_module`: holds `semantics` + `rtl` + memo maps. A structured syntax node maps to its semantic record (the record whose `syntax` is the node's index), then to its RTL identity through that RTL record's provenance field (`semantic_module`, `semantic_signal`).

Emission rule: a `PIGEN_SYNTAX_OPAQUE` node → OPAQUE item (its `location.source_span`); a node lowering to a published RTL identity (module/object/instance/equation/process) → the matching structured item, the MODULE node opening its nested scope with its children nested inside. A required node (module, or signal declarator) with no published identity is reported at its span by the missing-lowered-identity diagnostic — its public shape is established here, its span-reporting and stop-on-error wiring is the next in-order step.

Build seam: `make output-model-test` compiles `tests/output_test.c` + the full parse+lower pipeline (src/output.c, src/rtl_lower.c, src/rtl.c, src/resolve.c, src/type_resolve.c, src/expression_analysis.c, src/expression_resolve.c, src/expression_use.c, src/predicate.c, src/operation.c, src/transfer_type.c, src/integer.c, src/data_type.c, src/semantic.c, src/syntax.c, src/type_syntax.c, src/expression.c, src/preprocess.c, src/lexer.c, src/source.c, src/util.c). t9-skeleton calls the 4-arg walk and pins the ownership rule (every NULL-argument call and a clean walk leave `*error` unset) and the full `pigen_output_error_is_set` contract: 1 for a non-NULL message with a valid span (`start <= end`, including equality), 0 for an invalid span (`start > end`) even with a message, 0 for a NULL message, 0 for a NULL error — the invalid-span pin rejects the drop-span-check shortcut. t9-build-walk pins per-declarator identity MATCH: a source-order recursive mirror of the walk (a flat sibling iteration reverses order) requires each emitted `PIGEN_OUTPUT_RTL_OBJECT` item, in item-array (DFS) order, to equal the object independently resolved for its own declarator (the semantic signal whose `syntax.index` is the node's index, then the object whose `semantic_signal` is that signal). The weaker general pin (every structured slot non-INVALID) is kept separately. On the witness (module top; logic clk, d; always @(posedge clk) d <= clk;) it pins clk→object[0] and d→object[1], rejecting a walk that emits object[0] for d. t9-nesting, t9-failed-append and t9-coverage do not call the walk and are unchanged.

Coverage gate: `pigen_output_validate_coverage` is correct and unchanged. The t9-build-walk pin is bounded to the walked model's OPAQUE items being source-ordered and non-overlapping (no OVERLAP/REVERSAL), plus the module-range prefix and OPAQUE in-bounds/non-decreasing readback: the parser's OPAQUE nodes are token-extent, so whitespace and a structured item's own extent are not OPAQUE-spanned, and the gate skips structured items.
