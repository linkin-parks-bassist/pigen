pigen_build_output_model walks parsed syntax against completed lowering, fills an ordered output model and appends semantic module specializations. Child order is preserved with package namespace preparation.

Interface: `int pigen_build_output_model(pigen_output_model *model, const pigen_syntax_tree *syntax, const pigen_rtl_lowering *lowering, pigen_output_error *error);` Success returns 0; failure returns -1 and stops, possibly leaving partial output state (how/should/compiler/builders/fail.md). The optional error pointer receives a diagnostic when the failing branch reports one. NULL model/syntax/lowering return -1 after zeroing a supplied error. A clean walk leaves it unset.

include/pigen/output.h defines pigen_output_error as a source span plus borrowed static message; it owns no string. Missing required RTL identities report the syntax node's location.source_span. pigen_output_error_is_set requires a non-NULL error/message and span.start<=span.end, including empty spans. NULL errors/messages and reversed spans return false; an unset error is all-zero. A -1 without a diagnostic is distinct from a reported missing identity.

Syntax nodes carry parent/first_child/last_child/next_sibling IDs and locations. Walk from COMPILATION_UNIT through each ordered child chain. OPAQUE nodes hold preserved written regions and trivia. Completed pigen_rtl_lowering owns semantics, RTL and memo maps. Outside generated templates, a structured syntax ID selects its semantic record, then its RTL identity through semantic_module/semantic_signal provenance.

GENERATE_REGION templates and COMBINATIONAL_PROCESS bodies are skipped; typed module records supply selected hardware and hoisted procedural locals (how/are/structured/generate/scopes/elaborated.md). PARAMETER/GENVAR/RETAINED/INSTANCE items preserve SV through prepared text or spans. Specialized modules consume finished parameter/instance records (how/are/generated/child/parameters/specialized.md). Extern MODULE declarations and their specialization bodies emit nothing; their instances use prepared RTL records (how/are/native/axi/endpoints/mapped/to/external/systemverilog/ip.md). Other MODULE nodes open a nested layout; MODULE and SIGNAL_DECLARATOR require published identities and otherwise report their own span. Owned DATA TYPEDEF nodes prepare root/module/package declarations; native aliases emit none (how/are/data/typedefs/emitted.md). Other unmapped containers recurse. Continuous assignments publish equations through module records.

PACKAGE has no RTL module identity. Its children preserve ordinary declarations, prepare source-point DATA/constant imports and defer exports before the closing wrapper (how/are/native/axi/package/exports/represented.md). Actual routine imports also publish canonically after the header. Retained callee tokens render from semantic target/package identities, preserving surrounding bytes or expanding macro tokens (how/are/retained/package/calls/bound.md). IMPORT suppresses native protocol types and preserves ordinary bindings (how/are/native/axi/package/imports/resolved.md). Structured procedural imports are compile-time-only and never hoisted (how/are/procedural/package/imports/resolved.md). Terminal emission consumes the completed layout without semantic lookup.

make output-model-test builds tests/output_test.c with src/output.c, rtl_lower.c, rtl.c, resolve.c, type_resolve.c, expression_analysis.c, expression_resolve.c, expression_use.c, predicate.c, pipeline_identity.c and the Makefile's SEMANTIC_SOURCES/SYNTAX_SOURCES groups. Its T selector chooses a fixture.

The t9-skeleton fixture checks the four-argument walk, unset diagnostics on NULL arguments/clean output, and every error_is_set boundary, including equality and reversed spans. t9-missing-identity tests positive completed lowering, deleted module records and invalidated object semantic_signal IDs; failures identify the introducing MODULE/declarator. t9-build-walk independently mirrors source-order DFS and matches every emitted RTL_OBJECT to its own declarator's semantic signal and RTL object. It pins clk to object[0] and d to object[1], so assigning any valid object is insufficient. A separate pin checks non-invalid structured slots. t9-nesting/t9-failed-append/t9-coverage exercise layouts directly. Cleanup restores hidden module counts and frees coverage sources before owned names.

Coverage checks OPAQUE source order, bounds, overlaps/reversal, module child ranges and trailing root trivia. The build-walk witness requires following root items to be OPAQUE at or after the module span end. syntax.c:add_opaque_bytes records byte extents; add_opaque covers written bytes up to the next owned item's first byte, including whitespace. Structured/RETAINED items have separate slots and are skipped by OPAQUE coverage validation. Package wrapper ownership is detailed in how/should/ordered/output/preserve/opaque/sv.md.
