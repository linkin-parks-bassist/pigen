A test harness must build and execute each artifact in a fresh, invocation-owned directory and clean it up, so a run observes only the binary it just compiled. A fixed shared output path is a defect: if another build or editor writes the same path between compile and execute, the harness runs a different binary than it compiled, and a source that genuinely fails reports pass.

The production `Makefile` C compile/execute targets — the fifteen `pigen-*-test` targets from `source-test` through `sv-emit-test` — satisfy this: each first `rm -f`s its own legacy fixed path `/tmp/pigen-<name>`, creates a fresh directory (`mktemp -d`), compiles the unchanged source list and `CFLAGS` into `$dir/<name>` (a compile failure still propagates nonzero), runs `$dir/<name>` preserving any `$(T)` section-selection argument, exits with the run's status, then removes the directory. The SV/pipeline/waveform targets (`.sv`/`.vvp`/`.verilator` products for separate simulator runs) are outside this concern.

`tests/**` and `Makefile` are protected harnesses; an implementation worker must not edit them, and the landing gate refuses an implementation-stage commit that changes them. The repair therefore routes through the test-contract lane, which owns both.

The hidden red pin `tests/harness_artifact_ownership.sh` (one `contracts.json` entry, `sh tests/harness_artifact_ownership.sh`) witnesses the property on all fifteen targets, `source-test` being the representative. It is RED on the fixed-path Makefile and green only under the mktemp form. Its witness is STATE-BASED (post-run) and bounded by what the correct form leaves observable: the correct form `rm -f`s the fixed path and builds in a fresh dir, so a successful run leaves the fixed path ABSENT — post-run state cannot prove the run used the owned dir, and it cannot catch the build-to-fixed-then-delete escape. That escape compiles the real test to the fixed path (truncating any pre-placed sentinel in place: `cc -o` reuses the existing file's inode), executes the freshly compiled binary (not the sentinel, so no marker), then `rm -f`s the path; its final state (path absent, no marker, rc 0) is byte-for-byte identical to the correct form. Only an event-based watch of the fixed path during the run (inotify: Linux-only, racy, not POSIX sh) or a contract change leaving a durable per-run trace could separate the two. Catching that escape is a product decision, not a witness technique, and is not made by this pin.

What the state-based witness does pin, per target: (1) NO FIXED PATH — a clean run leaves no executable at `/tmp/pigen-<name>`; (2) NO FIXED-PATH EXECUTANT-REUSE — a RUNNABLE sentinel pre-placed on the fixed path must not fire (catches a harness that runs the fixed-path occupant without recompiling). Both hold on the mktemp form.

Current state: MET on `master` — all fifteen targets build in a fresh `mktemp -d` directory, first clear their own legacy fixed path, and clean up; no fixed `/tmp/pigen-<name>` executable is written after a run and a compile failure still propagates nonzero. The hidden pin stays ledger-held and red-on-the-old-form; the corrected Makefile form is on master.
