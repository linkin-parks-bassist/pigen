A test harness must build and execute each artifact in a fresh, invocation-owned directory and clean it up, so a run observes only the binary it just compiled. A fixed shared output path is a defect: if another build or editor writes that path between compile and execute, the harness runs a different binary than it compiled, and a failing source reports pass.

The production `Makefile` C compile/execute targets — the fifteen `pigen-*-test` targets from `source-test` through `sv-emit-test` — satisfy this: each first `rm -f`s its own legacy fixed path `/tmp/pigen-<name>`, creates a fresh directory (`mktemp -d`), compiles the unchanged source list and `CFLAGS` into `$dir/<name>` (a compile failure still propagates nonzero), runs `$dir/<name>` preserving any `$(T)` section-selection argument, exits with the run's status, then removes the directory. The SV/pipeline/waveform targets (`.sv`/`.vvp`/`.verilator` products) are outside this concern.

`tests/**` and `Makefile` are protected harnesses; an implementation worker must not edit them, and the landing gate refuses an implementation-stage commit that changes them. The repair routes through the test-contract lane, which owns both.

The pin `tests/harness_artifact_ownership.sh` (one `contracts.json` entry, `sh tests/harness_artifact_ownership.sh`) witnesses the property on all fifteen targets, `source-test` being the representative. Its witness is state-based (post-run), per target: (1) NO FIXED PATH — no executable left at `/tmp/pigen-<name>`; (2) NO FIXED-PATH EXECUTANT-REUSE — a RUNNABLE sentinel pre-placed on the fixed path must not fire (catches a harness that runs the fixed-path occupant without recompiling); (3) INVOCATION-OWNED DIR CLEANED — the fresh `mktemp -d` directory must be removed, so no `/tmp/tmp.*` created during the run survives after it. All three hold on the correct mktemp form; property 1 is red on the fixed-path form (it leaves the ELF).

Feasibility boundary. Property 3 CATCHES the "leaves the invocation-owned directory behind" escape: a leftover `mktemp -d` dir is durable and observable post-run, so the witness records the pre-run set of `/tmp/tmp.*` and fails if any created during the run survive. The one uncatchable case is the build-to-fixed-then-delete escape: it compiles to the fixed path (truncating the sentinel in place, `cc -o` reuses the inode), runs the fresh binary (no marker), then `rm -f`s the path; its final state (path absent, no marker, rc 0, no leftover dir) is byte-for-byte identical to the correct form. Only an event-based watch during the run (inotify: Linux-only, racy, not POSIX sh) or a contract change leaving a durable per-run trace separates the two; catching that escape is a product decision, not a witness technique, and is not made by this pin.

Current state: MET on `master` — all fifteen targets build in a fresh `mktemp -d` directory, clear their legacy fixed path, run it, and remove the directory; no fixed `/tmp/pigen-<name>` executable or leftover `/tmp/tmp.*` directory is left, and a compile failure propagates nonzero. The pin's third property is added through the test-contract lane; the corrected Makefile form is on master, and the pin is green under it and red under the old fixed-path form.
