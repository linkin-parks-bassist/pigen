tests/pipeline_output_test.c is the discriminating test contract for pipeline step (a): the pipeline identifier as a module-scope buf output packet identity (plan: what/is/the/plan.md, step (a); spec: what/is/the/spec.md; gates: what/are/the/remaining/architecture/migration/gates.md). It pins the owner seam include/pigen/pipeline_identity.h + src/pipeline_identity.c (pigen_pipeline_identifier_establish / pigen_pipeline_identifier_of), which on master return the invalid sentinel until the implementation stage lands. It is a four-section manifest wired as one `make pipeline-output-test T=<section>` entry per section in tests/contracts.json (four entries); the Makefile target compiles the test with the exact CFLAGS (-std=c17 -Wall -Wextra -Wpedantic -Werror -O2 -Iinclude) against src/pipeline_identity.c plus the semantic and syntax owners.

The pinned law is the buf output identity: the pipeline identifier names exactly one module-scope signal whose transfer type is buf and whose direction is a module output, whose data type is the outgoing packet aggregate (the concatenation, in source order, of the outgoing field data types via pigen_data_type_concatenation), bound to a module-scope symbol recoverable through the module's symbol/signal set and pigen_symbol_signal, with the symbol and signal spans anchored at the identifier's original token span. Every field is a buf (omission canonical, explicit buf equivalent, one dialect) and the output packet carries that same buf.

Every witness is built through the owner APIs: the source is parsed to obtain the PIGEN_SYNTAX_PIPELINE node, the identifier token span (through the expanded-token origin), the field declarations and the clocked-process clock span, and the semantic model (module, module scope, clock signal/domain, clocked process) is built directly via the semantic owners. The witness cannot lower the module through pigen_resolve_semantics: the structured resolver rejects a clocked process containing a pipeline, so the model is constructed directly and the skeleton's establish/accessor entry points are driven on top of it.

The four sections, each red at the establish REQUIRE against the current stub and each independently discriminating, green once the implementation lands:
- output-identity: a single 8-bit field yielded; the identifier resolves to exactly one module-scope signal with transfer type buf AND direction a module output. A builder that drops the output direction or a non-buf transfer type fails.
- outgoing-packet-type: the established signal's data type is the outgoing packet aggregate, pinned by packed width - a single 8-bit field gives an 8-bit packet, and a two-field {8-bit, 16-bit} pipeline gives a 24-bit packet (the sum, not one field's raw type). A mis-typed or mis-width outgoing packet fails.
- module-scope-binding: the identifier is bound to a module-scope symbol (its scope is the module scope whose parent is the compilation scope, not a stage-/pipeline-local child scope), recoverable via pigen_symbol_signal and present in the module's signal set, with the symbol and signal spans anchored at the identifier's original span. A stage-local binding or a mis-anchored span fails.
- buf-field-consistency: every field is a buf and the established output packet's transfer type is that same buf, pinned from both an omitted-buf single field and an omitted+explicit-buf pair. A non-buf field or an output packet carrying a different transfer type fails.

Discrimination: a builder that drops the output direction, mis-types the outgoing packet, or introduces the identifier into a private scope fails its section. The prior pipeline-identity-test (sections shape/field-buf/scope/yield) stays green and the full registered manifest carries the four entries. No production switch, no second dialect, no fallback, no prototype-parity.
