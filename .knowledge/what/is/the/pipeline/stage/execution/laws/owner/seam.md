The pipeline stage execution-laws owner is the structured-path owner seam that turns one stage of a parsed pipeline (a PIGEN_SYNTAX_STAGE child of the PIGEN_SYNTAX_PIPELINE node) into that stage's execution-law view in the resolved semantic model. It is a new structured owner and the sibling of the pipeline identifier identity owner (include/pigen/pipeline_identity.h + src/pipeline_identity.c); it is a different owner from the quarantined textual prototype's include/pigen/pipeline.h / src/pipeline.c, which it does not touch, reuse, or link to.

The seam is established on master as include/pigen/pipeline_stage.h + src/pipeline_stage.c. The header defines pigen_pipeline_stage, one stage's execution-law view, carrying: syntax, the stage node's PIGEN_SYNTAX_STAGE id; first_write and write_count, the stage's outgoing field writes (the nonblocking `<=` items, as the syntax ids of the stage's nonblocking-assignment nodes in source order); first_read and read_count, the stage's consuming external/module-scope reads (as the syntax ids of the read nodes in source order); and in_bits and out_bits, the total $bits of the incoming fields the stage reads and the total $bits of the outgoing fields it writes. An invalid view carries the PIGEN_INVALID_ID sentinel in syntax, first_write and first_read, a write_count of 0, a read_count of 0, and in_bits / out_bits of 0. The entry point pigen_pipeline_stage_laws(pigen_semantic_model *model, pigen_syntax_id syntax, pigen_module_id module, const pigen_syntax_node *pipeline, const pigen_expanded_source *expanded, pigen_pipeline_stage *out) establishes one stage's view and validates the stage execution laws; the accessor pigen_pipeline_stage_is_invalid(const pigen_pipeline_stage *) returns 1 on an invalid view.

The full stage-execution-law contract is documented in the header: the first stage cannot read a pipeline field that is not initialized (it may only read external or module-scope signals, which are already live); a later stage reads only the immutable incoming fields handed by the earlier stages, not a field the chain has not written; each `<=` writes exactly one outgoing field, visible in the following stage; every boundary between adjacent stages keeps an equal total $bits (in_bits == out_bits), so the chain neither widens nor narrows the packet it carries; an external consuming read is atomic under the full guard; and at most one item per cycle.

The seam's entry point currently returns -1 and leaves the out view invalid (PIGEN_INVALID_ID in the syntax id and first_write / first_read, zero counts and zero bits), fail-loud with no rollback (how/should/compiler/builders/fail.md), until the law logic is implemented; a failed call reports the diagnostic and the compile stops, and nothing uses the model after a failed compile, so no caller or test asserts a failure left the model unchanged. The law logic — validating the laws and populating a stage's view, atomic external inputs/reset, repartition and one-item-per-cycle — and the step-(b) discriminating test manifest are not yet implemented; they are the remaining step-(b) work over this seam.
