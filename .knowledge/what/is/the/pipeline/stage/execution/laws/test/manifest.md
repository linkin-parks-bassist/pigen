Scope: of the six named stage-execution laws, EXACTLY the four that are source-level discriminable are pinned here; the two that have no source-level red form are NOT part of this manifest (see below). Each section is a red+anchor discriminating pair: the red form constructs the failing state and asserts the diagnosed status (rc == -1), and the anchor is the legal form asserting the accepted status (rc == 0) plus the view shape (write/read counts, in/out bits, first_write id). Each section independently discriminates its named law — a builder that drops that law turns exactly that section red, and a permissive all-accept builder fails every section.

Pinned laws (the four sections):
- first-stage-external-reads: a first stage whose `<=` RHS names a pipeline field not yet produced by any earlier stage is diagnosed (rc == -1); a first stage reading only the enclosing module input is legal (rc == 0, one outgoing write, one consuming external read, zero incoming bits, out_bits the field width).
- later-stage-incoming-immutable: a later stage reading a field the previous stage did not write is diagnosed (rc == -1); a later stage reading only the immutable incoming field the previous stage wrote is legal (rc == 0, in_bits the incoming field width, out_bits the written field width, one outgoing write, no consuming external read).
- outgoing-visibility: each `<=` writes exactly one outgoing field visible in the following stage; a `<=` whose destination is a module input or a stage-local wire (not an outgoing field) is diagnosed (rc == -1); a `<=` writing a pipeline field is legal (rc == 0, write_count 1, out_bits the field width).
- repartition-equal-bits: adjacent stage packets may differ in member count and widths but the complete packed bit streams keep an EQUAL total $bits; an equal-total two-field repartition (stage 1 writes a (8) and b (8) from x and y — a 16-bit outgoing packet; stage 2 reads {a, b} (16-bit incoming) and writes c (16-bit) — equal total $bits at the boundary) is legal (rc == 0, in_bits == out_bits == 16), while a boundary whose total $bits differ (stage 2 reads {a, b} = 16 bits but writes c = 8 bits) is diagnosed (rc == -1).

Witnesses are built through the owner APIs: each section parses a legal pipeline through the structured syntax path to obtain the pipeline node, its stage children, the nonblocking-assignment nodes, the name-expression token origins and the field declarator name spans, builds the surrounding resolved module through the semantic owners (the same module-scope skeleton the resolver builds for a clocked process, since the structured lowerer does not yet carry a pipeline statement through pigen_resolve_semantics — a later pipeline step), and drives the seam entry point, reading back only through the owner accessors. Every witness is located through the parse; every expected width is computed from the parsed node (field widths from the [hi:lo] span within the field's own declaration; the total $bits as their sum), never by a source-text search over the output. No prototype reuse, no editing of the prototype's pipeline witnesses.

The two named laws with no source-level red form are NOT in this manifest: "an external consuming read is atomic under the full guard" is a temporal property (the stage waits for all inputs and consumes on advance under the complete enclosing guard) with no statically discriminable under-guarded read form in the unguarded model, and "at most one item per cycle" is a storage-level invariant on the one-entry buf (what/is/a/buf.md) — a stage may legally carry several `<=` (how/to/write/pipeline/stages.md), which is exactly the multi-field form the repartition anchor requires, so it has no contract-level negative witness. Both are pinned by the step-(c) parent-module lowering's emission/behavioral witnesses, which the step-(c) step owns.
