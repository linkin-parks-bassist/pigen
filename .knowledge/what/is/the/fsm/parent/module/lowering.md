The FSM is implemented on the structured production path: src/syntax.c parses one module-level `fsm` item into PIGEN_SYNTAX_FSM with ordered level-zero statements and PIGEN_SYNTAX_FSM_STATE children, each state body one ordinary statement; include/pigen/syntax.h carries the optional name (has_name), the clock expression and the state/goto nodes with original spans. src/resolve.c resolves the optional/anonymous FSM into one shared-model process: a state register symbol (the FSM name, or a synthetic internal name for an anonymous FSM), a state-active condition per state, level-zero statements under the plain guard, ordinary reset code, `when` event control and the first-goto termination rule. src/fsm_identity.c and src/fsm_lower.c are standalone owners recorded by fsm-identity-test and fsm-lower-test: the identity publishes the state type, state set, transition set and an initial state (the first level-zero goto's target, else the first declared state); the lowering is a structural stage that is not wired into production. Contract and limits: what/is/an/fsm.md and how/to/write/fsm/states.md. Startup without reset remains an open decision (what/is/the/plan.md).
