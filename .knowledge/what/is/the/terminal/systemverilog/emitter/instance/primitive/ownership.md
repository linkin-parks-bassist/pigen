The whole-design golden (what/is/the/terminal/systemverilog/emitter/contract.md) renders an instance as `  instance #(.DEPTH(8)) fifo (.clk(clk));`: the instance's final NAME is the synthetic role stem `instance`, but the line also shows the instantiated primitive's definition name (`fifo`) and each parameter's name (`DEPTH`). Those two spellings are not yet ownable by the structured emitter, so the instance line is the one part of the golden a contract-consistent, no-hardcoding emitter cannot render.

What the record owns (include/pigen/rtl.h, `pigen_rtl_instance`): `origin`, `semantic_module` (a `pigen_module_id`, provenance and invalid when the instance is synthetic), `parameters` (an ordered range of value expressions only — the depth literal 8, no parameter-name text), `connections` (object IDs), and `module` (invalid until a later owner-resolution stage publishes it). The final NAME `instance` comes from `pigen_rtl_assign_names` for an invalid-origin INSTANCE request (role stem, src/rtl_name.c).

What is missing: (1) no owner API resolves a `pigen_rtl_module_id` to a primitive definition name such as `pigen_fifo`; the prototype's `pigen_prototype_transfer_descriptor.primitive_module` and `pigen_primitive` are textual-path machinery the emitter's structural boundary (what/is/the/terminal/systemverilog/emitter/contract.md) forbids it from consulting. (2) no record carries a parameter-name spelling; `parameters` holds only value expressions. what/is/elastic/rtl/task/six.md section 13 states this explicitly: "there is no owner API resolving a pigen_rtl_module_id to a primitive definition name ... That mapping is a design decision the implementation fills."

Consequence for the whole-design step: until an owner publishes a primitive-definition-name and parameter-name spelling (or the witness/contract is re-scoped so the instance line is representable from owned records), `pigen_emit_systemverilog` cannot emit the instance's `fifo`/`DEPTH` without hardcoding fixture strings — which the user forbids and the structural boundary forbids. This is an open ownership gap, not an emitter defect: the emitter walk for the representable kinds (OPAQUE, MODULE, RTL_OBJECT, RTL_EQUATION, RTL_PROCESS, and the instance's own name) is complete and contract-consistent. Resolution is the t10 contract/fixture coherence review.
