Ordered output model. Create output.h/output.c/output_test.c. Layout-only items are opaque source spans or matching structured module/object/instance/equation/process IDs. Walk syntax child order, preserve trivia/separators as opaque spans, require every structured node to have lowered identity. Shape implemented: include/pigen/output.h and src/output.c expose the ordered output model. `pigen_output_kind` has the six kinds OPAQUE, MODULE, RTL_OBJECT, RTL_INSTANCE, RTL_EQUATION, RTL_PROCESS. `pigen_output_item` holds the kind plus exactly one payload — for OPAQUE a `pigen_source_span`, for a structured kind the matching structured identity (a value copy, no ownership transfer) — and a `pigen_rtl_record_range layout` (the item's half-open nested-item range in the same array, meaningful for a module item and empty otherwise). `pigen_output_model` owns the ordered item array and a parallel per-module nested-layout range array, with count/capacity fields. The public API: `pigen_output_model_init` (zeroes), `pigen_output_item_add` (appends by value, returns the slot index or PIGEN_INVALID_ID), `pigen_output_item_count`, `pigen_output_item_get` (zero item out of range), `pigen_output_item_kind` (OPAQUE out of range), `pigen_output_item_span` (all-invalid span for a non-opaque or out-of-range slot), the five kind-typed identity accessors (`_module`, `_object`, `_instance`, `_equation`, `_process`; PIGEN_INVALID_ID identity for a non-matching or out-of-range slot), `pigen_build_output_model` (stub: returns 0 with zero items) and `pigen_free_output_model` (frees and zeroes: NULL pointers, zero counts). No API returns or searches opaque source text; the model never validates structured identities against an RTL owner. A failed call returns 0/-1 or the PIGEN_INVALID_ID identity and may leave partial state; no test asserts what a failure left (how/should/compiler/builders/fail.md).

Build seam: Makefile target `output-model-test` compiles tests/output_test.c + src/output.c + src/source.c + src/util.c under the -Werror C17 line and runs the binary with $(T). tests/contracts.json carries the entry covering src/output.c + src/source.c + src/util.c, command make output-model-test T=t9-skeleton. The self-contained t9-skeleton section pins the shape: a freshly inited model has zero items and no owned arrays; after appending one opaque item (a known span) and one structured item (a known RTL object identity) both read back exactly their stored span / identity; querying either item for a kind it is not returns PIGEN_INVALID_ID (and an all-invalid span for a non-opaque slot); the builder stub succeeds with zero items; after pigen_free_output_model the model is zeroed (array pointers NULL, counts 0). make output-model-test T=t9-skeleton prints PASS: t9-skeleton and exits 0; rtl-test stays green.

Remaining frontier, in order: (1) append and child/nesting ownership — the module record's nested layout range is currently a passive value copied by the caller; (2) the exact monotonic-coverage gate rejecting gaps, overlaps, reversal, wrong-source and invalid refs; (3) failed nested append restoring layout/item/child counts; (4) pigen_build_output_model walking syntax child order against the lowering mappings (trivia/separators preserved as opaque spans; syntax declarations/processes via recorded mappings); (5) the missing-lowered-identity diagnostic at the original structured syntax span. The pigen_rtl_module owner ranges (objects, instances, equations, processes) are the structured identities the output layout references.
