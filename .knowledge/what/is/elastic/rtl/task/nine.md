Shape implemented: include/pigen/output.h and src/output.c expose the ordered output model. `pigen_output_kind` has the six kinds OPAQUE, MODULE, RTL_OBJECT, RTL_INSTANCE, RTL_EQUATION, RTL_PROCESS. `pigen_output_item` holds the kind plus exactly one payload — for OPAQUE a `pigen_source_span`, for a structured kind the matching structured identity (a value copy, no ownership) — and a `pigen_rtl_record_range layout` (the half-open nested-item range, meaningful for a module item, empty otherwise). `pigen_output_model` owns the ordered item array and a parallel per-module nested-layout range array. The API: `pigen_output_model_init`, `pigen_output_item_add` (returns slot or PIGEN_INVALID_ID), `pigen_output_item_open` / `_add_child` / `_layout` (owner-managed nesting), `pigen_output_item_count`, `pigen_output_item_get`/`_kind`/`_span` (out-of-range reads a zero/OPAQUE/all-invalid value), the five kind-typed identity accessors (PIGEN_INVALID_ID for a non-matching/out-of-range slot), `pigen_build_output_model` (stub: 0 with zero items) and `pigen_free_output_model` (frees both arrays, zeroes to NULL pointers and zero counts). No API returns opaque source text; the model never validates structured identities against an RTL owner; a failed call returns 0/-1 or PIGEN_INVALID_ID and may leave partial state (how/should/compiler/builders/fail.md).

Nesting ownership: a module's nested-layout range is owner-managed, not caller-set. `pigen_output_item_open(model, item)` appends a module item and opens its nested scope — the range starts empty (first = module slot + 1, count = 0), the caller layout is discarded, and the range is recorded in `nested_layouts` keyed by the module's arena index. `pigen_output_item_add_child(model, module, child)` appends a child into that open scope (count += 1) and keeps the module item's `layout` in lockstep; PIGEN_INVALID_ID for an unknown module identity. `pigen_output_item_layout(model, module_slot)` reads the owner range, {0,0} for no scope/missing identity/out-of-range slot; a child-less module keeps {slot+1, 0}; the array's grown tail is zeroed so a sparse identity reads empty until opened.

Monotonic-coverage gate (now being built): a pure read-only `pigen_output_coverage_result pigen_output_validate_coverage(const pigen_output_model *, const pigen_source_manager *)` validates the model's OPAQUE spans against one source in slot order — a contiguous, non-overlapping, in-source, monotonic run whose first start is 0 and whose cursor reaches the source's end exactly. Structured items carry no span and are skipped; the gate never validates structured identities against an RTL owner. `pigen_output_coverage_reason` is OK / EMPTY (no OPAQUE items) / GAP (a span starts after the cursor, or a trailing gap leaves it short) / OVERLAP (a span starts before the cursor, or overshoots) / REVERSAL (a span's end <= its own start) / WRONG_SOURCE (a span's source differs from the manager's single source) / INVALID (a span fails `pigen_source_span_valid`); the result is `{int ok; pigen_output_coverage_reason reason}`. The API shape (enum, result struct, declaration) and a shape-only NULL stub are landed first; the exact walk, the expected-end source-length bound, and the reason logic, plus the test packet, arrive next.
