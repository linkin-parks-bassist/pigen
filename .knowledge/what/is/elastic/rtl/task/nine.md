Shape implemented: include/pigen/output.h and src/output.c expose the ordered output model. `pigen_output_kind` has the six kinds OPAQUE, MODULE, RTL_OBJECT, RTL_INSTANCE, RTL_EQUATION, RTL_PROCESS. `pigen_output_item` holds the kind plus exactly one payload — for OPAQUE a `pigen_source_span`, for a structured kind the matching structured identity (a value copy, no ownership) — and a `pigen_rtl_record_range layout` (the half-open nested-item range, meaningful for a module item, empty otherwise). `pigen_output_model` owns the ordered item array and a parallel per-module nested-layout range array. The API: `pigen_output_model_init` (zeroes), `pigen_output_item_add` (appends by value, returns slot or PIGEN_INVALID_ID), `pigen_output_item_open` / `pigen_output_item_add_child` / `pigen_output_item_layout` (owner-managed nesting, below), `pigen_output_item_count`, `pigen_output_item_get` (zero item out of range), `pigen_output_item_kind` (OPAQUE out of range), `pigen_output_item_span` (all-invalid span for a non-opaque/out-of-range slot), the five kind-typed identity accessors (PIGEN_INVALID_ID identity for a non-matching/out-of-range slot), `pigen_build_output_model` (stub: 0 with zero items) and `pigen_free_output_model` (frees both arrays, zeroes to NULL pointers and zero counts). No API returns opaque source text; the model never validates structured identities against an RTL owner; a failed call returns 0/-1 or PIGEN_INVALID_ID and may leave partial state (how/should/compiler/builders/fail.md).

Nesting ownership: a module's nested-layout range is owner-managed, not caller-set. `pigen_output_item_open(model, item)` appends a module item and opens its nested scope — the range starts empty at the end of the item array (first = module slot + 1, count = 0), the caller layout is discarded, and the range is recorded in `nested_layouts` keyed by the module's arena index (identity); returns the module slot. `pigen_output_item_add_child(model, module, child)` appends a child into that open scope (count += 1) and copies the updated range back into the module item's `layout` to keep it in lockstep; returns the child slot (PIGEN_INVALID_ID for an unknown module identity). `pigen_output_item_layout(model, module_slot)` reads the owner-managed range, returning {0,0} for a module with no owned scope, a missing identity, or an out-of-range/invalid slot. A child-less module keeps {slot+1, 0}. `nested_layouts` is keyed by arena index with its grown tail zeroed so a sparse identity reads empty until opened.

Build seam: Makefile `output-model-test` compiles tests/output_test.c + src/output.c + src/source.c + src/util.c under -Werror C17 and runs the binary with $(T); tests/contracts.json carries the entry (make output-model-test T=<section>). t9-skeleton pins the shape (zero items on init, span/identity read-back, wrong-kind PIGEN_INVALID_ID, free zeroes). t9-nesting pins the owner-managed range (opened module reads {slot+1, 0} regardless of caller layout; two children make {slot+1, 2} in append order with the module layout in lockstep; a child-less module reads {slot+1, 0}; a passive module and a missing/invalid/out-of-range slot read {0,0}; freeing zeroes both arrays). Both print PASS and exit 0; rtl-test stays green.
