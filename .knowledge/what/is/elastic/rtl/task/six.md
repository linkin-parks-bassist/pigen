Task 6 owns the transfer-realization declaration endpoints in include/pigen/rtl_lower.h and src/rtl_lower.c, on master. `pigen_lower_rtl_module_declarations(pigen_rtl_lowering *, pigen_module_id)` is the entry point with an int error contract: a failed call reports -1, the compile stops, and partial state may remain (how/should/compiler/builders/fail.md). `pigen_rtl_signal_endpoints` holds the payload object id, valid/ready expression ids, and input_payload/input_valid/input_ready object ids. `pigen_rtl_lowering` carries a signal-indexed `lowered_endpoints` map (keyed by pigen_signal_id.index, grown on demand via `endpoint_map_ensure`); init zeroes it and free releases it.

Dispatch is by realization, never by source transfer enum: a private (static, file-local) `realization_endpoint_adapters` table in src/rtl_lower.c, one entry per valid realization (BOUNDARY, COMBINATIONAL_NET, PROCEDURAL_VARIABLE, ELASTIC_SLOT, PULSE_REGISTER, PARAMETERIZED_QUEUE, SKID_QUEUE). The source descriptor is read only to select the realization; capacity/depth/ready/occupancy/reset come from the realization's descriptor. A structural check must find no PIGEN_TRANSFER_TYPE_(ABSTRACT|WIRE|REG|LOGIC|BUF|PORT|FIFO|SKID) matches in rtl_lower.c.

Endpoint shapes. BOUNDARY is module-input only and publishes the three-port input shape (payload, valid, ready objects; the input side is the same three objects). ABSTRACT is its only source type: it is non-concrete with valid_constant = ready_constant = -1 and ready_dependency PIGEN_TRANSFER_READY_EXTERNAL, so a boundary signal carries NO constant controls — valid and ready are context-dependent external controls (what/is/an/abstract/input.md). The owner API makes the shape unambiguous: pigen_signal_add (src/semantic.c) rejects non-INPUT direction for non-concrete types, so no OUTPUT boundary, no NULL-descriptor signal and no INVALID-realization mapping is constructible. COMBINATIONAL_NET/PROCEDURAL_VARIABLE publish exactly one VARIABLE payload object (the lowered data type memo's type record, the semantic direction, the input side the same object) with no storage instance, plus two constant controls: a file-local helper builds the 1-bit unsigned logic type, interns the descriptor constant (interned by value, so both valid constants — 1 — share one record while the ready constants WIRE 0 / REG 1 differ), and publishes it through pigen_rtl_expr_add_literal; the control is an expression identity, not a published object. ELASTIC_SLOT/PULSE_REGISTER/PARAMETERIZED_QUEUE/SKID_QUEUE each publish exactly one VARIABLE payload object plus exactly one pigen_rtl_instance owned by the semantic module, using the signal's source span as the instance origin so instances in one module are mutually distinct; their valid/ready are driven by the primitive (downstream / occupancy / always-ready), so no constant control expression is published and the endpoints' valid/ready expression ids stay invalid. The primitive-name mapping (pigen_buf/pigen_port/pigen_fifo/pigen_skid) is not pinned by the contract: no owner API resolves a pigen_rtl_module_id to a primitive definition name, and the instance's module field is invalid until a later owner-resolution stage. PARAMETERIZED_QUEUE (FIFO) is the only storage realization with a parameter: its semantic depth is lowered from the signal's transfer argument const-expr through the pigen_lower_rtl_expression memo and published as the instance's single ordered parameter, so the value round-trips exactly; slot/pulse/skid carry no parameter (capacity is the descriptor's fixed_capacity constant).
