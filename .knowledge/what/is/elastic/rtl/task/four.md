Interface decision (settled by manager command resolve-task-4-name-allocator-interface): the allocator's signature is extended with a source-manager argument, pigen_rtl_assign_names(pigen_rtl_model *model, const pigen_source_manager *sources, const pigen_rtl_name_request *requests, size_t request_count). pigen_rtl_name_get is unchanged. The interface is extended rather than accepting a distinctness-only allocator because the Task 4 spec requires source roles to copy the provenance spelling of a checked identifier, which a signature with no source-manager access cannot honor (a distinctness-only allocator would not round-trip a source signal's spelling), and because the established pigen pattern is a const pigen_source_manager * argument for every span-to-text and span-validation operation (pigen_source_span_text/valid, pigen_preprocess, the semantic constructors) while pigen_rtl_model stays deliberately source-neutral and carries only provenance spans. The rtl-name-test target already links src/source.c, so the seam is clean.
