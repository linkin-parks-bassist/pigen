Verified identity contract (2026-09-30, rtl-name-identity-contract-reconcile): name identity is the role plus the origin span (source index and half-open byte range), per same_identity at src/rtl_name.c:39-47; request order is not part of identity. A published record or an in-call request is reused whenever identities match (requests_match, :56-60; in-call dedup, :186-195). Consequences: SOURCE requests use distinct checked spans, so they never share an identity; synthetic internal roles carry an invalid span, so each internal role has exactly one identity, and identical internal requests (e.g. two PIGEN_RTL_NAME_PAYLOAD with an invalid span) dedup to a single name (name_count grows by one, the second request reuses the first's id). The unique_name suffix loop therefore sees at most one fresh request per stem per call: a stem colliding with a copied SOURCE spelling takes _1, and the _2 and higher branch is unreachable under the current identity model.
