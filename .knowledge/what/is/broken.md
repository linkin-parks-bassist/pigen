The structured frontend and elastic RTL work remain incomplete. Passing focused tests do not establish full compiler acceptance.

- **Co-slice destination widths resolve to 1 bit for non-literal data types (fix committed, unlanded; X-prop witness split out).** `pigen_extract_signal_transfer` (src/assignments.c) sizes per-destination repartition shifts via `extract_bit_width_from_data_type`, which parses only a literal `[hi:0]`/`[hi:lo]` range and otherwise falls back to 1, so a typedef'd co-sliced destination is assigned the wrong slice and `examples/biquad_bank.pigen` emits a filter result of 0 instead of 1024. The verified fix `e9dadfd` (on branch work/coslice-typedef-width-impl, child of master d02c19d, touches only src/assignments.c) makes `extract_bit_width_from_data_type` return 0 for any data type it cannot size (typedef names, macro-bounded ranges, plain or sliced types) and sizes such a destination with the SystemVerilog `$bits(destination)` query in the width cast and the per-member shift sum, with literal ranges keeping the landed constant-width mechanism. It is not yet on master, so the defect is still present there; landing it turns `biquad-bank-test` and the pure typedef-width witness green. The width witness no longer bundles an out-of-contract `previous` X-propagation assertion (an uninitialized, never-reset state register read by `previous <= state` in a separate always block, which propagates X under single-edge stimulus); that X-propagation is tracked as its own red test-contract (accepted d509b5d) with its own witness, so the width contract and the X-prop contract each own exactly one mechanism.
