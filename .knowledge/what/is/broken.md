The structured frontend and elastic RTL work remain incomplete. Passing focused tests do not establish full compiler acceptance.

- **Co-slice gives the last destination the whole aggregate.** For a multi-destination co-sliced transfer the prototype assigns the full packed aggregate to the last destination instead of its slice. In `tests/coslice.pigen` (four 8-bit destinations) the emitted `state <= ({source + 8'd1, source + 8'd2, source, state}) >> 0;` assigns 32 bits to an 8-bit register; `tests/transfer_block.pigen` emits the same pattern (24 bits into 8). Verilog's implicit truncation keeps the low bits. Verilator reports both as `WIDTHTRUNC` warnings, which `make verify` does not treat as failures (its lint runs with `-Wno-fatal`). This violates the packed bit-stream order contract and would produce wrong values whenever the last destination is not the lowest slice.
- **Co-slice destination widths resolve to 1 bit for non-literal data types.** `pigen_extract_signal_transfer` computes per-destination shift widths with `extract_bit_width_from_data_type` (src/assignments.c), which parses only a literal `[hi:lo]` range in the destination's data-type string and returns 1 otherwise. For destinations whose data type is not a literal range (typedef'd or otherwise resolved widths), every repartition shift amount becomes 0, so each co-sliced destination is assigned the low bits of the aggregate instead of its slice. In `tests/coslice.pigen` the emitted `left`/`right`/`state`/`state_delay` all receive `aggregate >> 0`; because `state` has no reset, the values propagate as X and `coslice-test` passes vacuously (its mismatch checks compare against X, and `if (x)` is false). `examples/biquad_bank.pigen` (typedef'd `coef_t`/payload types) emits `>> (0 + 0 + 0)` shifts, and biquad-bank-test, slicing-test and signal-syntax-test fail in simulation on it.
- **The elastic RTL vertical slice is incomplete.** Tasks 6 (declaration lowering), 8 (atomic fire/identity), 9 (ordered output) and 10 (terminal SV emission) are complete; the terminal emitter renders a finished, named RTL lowering to SystemVerilog validate-first, committing no partial output. The remaining in-order steps are Task 11 (quarantined composition/simulation) and Task 12 (verification and accurate status); Task 7 (ready-cycle validation) is deferred to Pigen 1.0. The declaration-lowering contract and evidence are owned by `what/is/elastic/rtl/task/six.md`; the remaining vertical-slice steps, in order, by `what/is/the/plan.md`.
- **Structured frontend is unlinked from production ./pigen.** The production Makefile target still compiles the textual prototype rather than the structured syntax, resolution, semantic and RTL path. See does/the/structured/frontend/run/in/production.md.
- **Retained-subsystem build and frontend gaps.** Core, pipeline, FSM, child-instance and fabric are specified from the spec and built on the structured path, subject to what/are/the/remaining/architecture/migration/gates.md. Accepted parameter/type/aggregate/array/expression forms and macro concatenation/stringification/required arguments remain incomplete. Delete textual machinery only when the corresponding retained subsystem's structured path covers the spec.
- **`make verify` passes but does not fail on lint warnings.** With Verilator 5.020 and Icarus 13.0 installed, `make verify` exits 0. Its Verilator lint runs with `-Wno-fatal`, so width warnings such as the co-slice truncation above pass silently.
