## Test scenarios

One line = one later test-author scenario, one `test_*` function in tests/compile_test.c (target compile-test, registered in tests/contracts.json). Every scenario drives pigen_compile_source with a literal data-first source string and observes rc, result.systemverilog and the error diagnostic (message + span). The witness shape is the FSM_WITNESS macro of tests/fsm_lower_test.c: `module NAME(input logic clk, input logic rst, input logic start, output logic done);` then `fsm NAME @(posedge clk) reset (rst) initial idle` and a `begin ... end` body of `state IDENT:` items; the idle state carries `if (start) goto run;` and the run state carries `done <= 1;` then `if (!start) goto idle;`.

1. The FSM lowers into the parent module's emitted SV, replacing the silent empty module: the legal two-state witness compiles with rc == 0 and the emitted SV declares exactly ONE `module` (the parent) whose body is non-empty beyond the port header - an internal declaration, continuous assignment and/or clocked process.
2. The state register is one internal variable, reset to the header initial state's encoding resolved by the header token's text: a legal FSM whose header names the SECOND declared state (`initial run`, states idle then run) compiles with rc == 0 and the emitted SV (a) declares exactly ONE internal (non-port) logic object - the synthetic state register - wide enough for every state's encoding (a 1-bit register for the 2-state witness fails the pin), and (b) carries a reset path driving the register to the header-named state's encoding (a reset to the first declared state's encoding fails the pin). The set-level reset path is pinned standalone by fsm-lower-test section state-register-reset and the identity's text resolution by fsm-identity-test section establish-valid-args (both discriminative: the witnesses name a non-first state); this line witnesses both in the terminal emission.
3. Per-state action bodies are gated on state-active in the emission: the legal witness (the run state's body carries `done <= 1;`) compiles with rc == 0 and the emitted SV carries the run state's action as an equation on the module's `done` output that is conditioned on the state-active comparison between the state register and the run state's encoding - a register-read-free action equation, or an ungated one, fails the pin. The provenance binding is pinned standalone by fsm-lower-test section per-state-action-bodies; this line witnesses the gate's structural presence in the terminal emission.
4. Guard-gated goto transitions share the one state register as their single destination: the legal witness (one guarded goto per state, the guards mutually exclusive by `start` / `!start`) compiles with rc == 0 and the emitted SV carries one guard-gated next-state value per goto - each a conditional whose true branch is the goto target state's encoding and whose false branch holds the current state (register read) - every such conditional driving the ONE state register and all carried in ONE posedge-clocked process (the one synchronous controller); two processes, a second destination or a transition not reading the register fail the pin. The exclusion set is pinned standalone by fsm-lower-test sections guard-gated-transitions and structural-exclusion; this line witnesses guard gating and the shared single destination in the terminal emission.
5. A second RTL record is not published for the FSM: the legal witness compiles with rc == 0 and the emitted SV declares exactly ONE `module` (the parent) carrying the controller - the production step publishes through the parent module's existing shared RTL module record, so a second-record publish (whose children the output model drops) would leave the controller absent from the emitted module and fail lines 1-4. This line pins the shared-module-record law at the observation point the second-record failure shows.
