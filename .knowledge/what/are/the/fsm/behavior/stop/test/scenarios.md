## Scope

One test obligation from the FSM contract: **the FSM's behavior/stop facts are pinned, not just its set-level record contract** — (a) the state register resets to the HEADER initial state's encoding (the state the `initial IDENTIFIER` names, resolved by token text, not always the first declared state); (b) each state's action body runs only while that state is active (state-active gating); (c) each goto changes state only under its explicit enclosing guard and never implicitly waits for a transfer (the next-state value is conditioned on the guard so the state holds otherwise). Seam: `tests/fsm_lower_test.c` (target `fsm-lower-test`), one new `SECTION` per line with a `tests/contracts.json` entry (`make fsm-lower-test T=<section>`). The third scoped obligation of what/are/the/owners/of/the/pipeline/fsm/behavioral/test/obligations.md (section 3); plan item 9.

## Current coverage

`fsm-lower-test`'s four positive anchors (state-register-reset, per-state-action-bodies, guard-gated-transitions, structural-exclusion) pin only the SET-LEVEL record contract: a rc of 0, a synthetic register object driven by an owned record, an action destination bound by provenance to the `done` output, the register driven and read by a published expression, and one owned group holding the single shared register. They do NOT pin the reset VALUE (that it equals the header initial state's encoding), state-active gating or per-goto guard gating: the RTL record model (`pigen_rtl_equation`, `pigen_rtl_update`, `pigen_rtl_process`) carries no guard or enable field, so the gate expressions are invisible at set level. The (s5) implementation carries all three obligations structurally as published gate expressions: the reset update's value is a conditional over a structurally-present reset gate whose when-true branch is the header initial state's encoding; each state's action value is a conditional over the state-active comparison `state_read == encoding`; each goto's next-state value is a conditional over its guard placeholder with the target encoding when true and the register read when false. This list pins those structures; a lowering that keeps the set-level contract but drops the reset value, the state-active gating or the per-goto guard gating must fail at least one line.

## Test scenarios

One line = one later test-author scenario, registered as its own `SECTION` in `tests/fsm_lower_test.c` with a `tests/contracts.json` entry, built on the established seam helpers (`fl_parse`, `fl_unit`, `fl_drive`, the `fl_owned` record collectors) and the record-model arena API; each line cites its standalone pin or names the fixture prerequisite that makes it discriminating.

1. Reset value equals the header initial state's encoding: a legal two-state FSM whose declared states are `idle` then `run` and whose header names the NON-FIRST state as initial (`initial run`, per-state index 1) lowers to rc == 0, and the controller's synchronous process carries one reset-path update driving the state register whose value is a PIGEN_RTL_EXPR_CONDITIONAL whose when-true child is a PIGEN_RTL_EXPR_INTEGER of the state type with value 1 — the header-named state's index, not the first declared state's (an `initial idle`-style lowering that always resets to encoding 0 fails this line). Standalone pin: the reset update is the one whose origin span is the FSM node's span (every goto update's origin is its goto node's span, located through the parse), which distinguishes it from the goto-to-run transition whose when-true encoding is also 1; fixture prerequisite: a file-local non-first witness variant (the `FSM_WITNESS` macro names `initial idle`, the first state, and would let an always-first reset pass — the same non-first discipline how/to/write/a/discriminating/resolution/witness.md requires of the (s2) identity witness).
2. State-active gating on the action body: a legal two-state FSM whose `run` state (per-state index 1) carries the multi-statement body (`done <= 1;` then a guarded `goto idle`) lowers to rc == 0, and the action equation (destination the owned object bound by provenance to the module's `done` output) has a value that is a PIGEN_RTL_EXPR_CONDITIONAL whose condition is a PIGEN_RTL_EXPR_BINARY equal-comparison (PIGEN_BINARY_EQUAL) whose operands are the state register read (a PIGEN_RTL_EXPR_OBJECT naming the synthetic register) and a PIGEN_RTL_EXPR_INTEGER of the state type with value 1 — the action runs only while the run state is active (a lowering that publishes the action value ungated, as a bare constant, fails this line). Standalone pin: the state-active comparison is the only published BINARY expression whose right operand is an INTEGER of value 1, while every state encoding constant (one per declared state, values 0 and 1) is also published — the pin is the BINARY comparison's operand structure (register read compared to the state's encoding), which a constant-gate or ungated action cannot fake.
3. Per-goto guard gating of the next state: a legal two-state FSM whose `idle` state carries `if (start) goto run;` (target per-state index 1) lowers to rc == 0, and the update for that goto (origin the goto node's span, located through the parse) has a value that is a PIGEN_RTL_EXPR_CONDITIONAL whose when-true child is a PIGEN_RTL_EXPR_INTEGER of the state type with value 1 and whose when-false child is a PIGEN_RTL_EXPR_OBJECT naming the state register — the goto changes state only under its guard and the state holds otherwise (a lowering that publishes the transition ungated, as a bare target encoding, fails this line). Standalone pin: the per-goto origin span is the discriminator (each goto's update is located through its node's span, never a source-text search), and the when-false register read is the hold fact.
4. No transition ever waits for a transfer: a legal two-state FSM whose `run` state carries `if (!start) goto idle;` (target per-state index 0) lowers to rc == 0, and that goto's update value (origin the goto node's span) is a PIGEN_RTL_EXPR_CONDITIONAL whose when-true child is a PIGEN_RTL_EXPR_INTEGER of the state type with value 0 and whose when-false child is a PIGEN_RTL_EXPR_OBJECT naming the state register — the transition is keyed on the explicit enclosing guard alone, never on a handshake or transfer condition (a lowering that substitutes an implicit transfer wait for the guard fails this line). Standalone pin: the per-goto origin span plus the (target-encoding, register-read) conditional shape, mirroring line 3 for the second transition of the controller.
5. One synchronous controller, one reset path: a legal two-state FSM lowers to rc == 0, and the parent module record owns EXACTLY ONE PIGEN_RTL_PROCESS (clocked posedge, the synchronous controller of what/is/an/fsm.md) whose update range contains exactly goto_count + 1 updates — one per goto plus the single reset-path update — all driving the single shared state register (a lowering that splits the controller across two processes, publishes a second reset path, or drops the reset update from the process fails this line; this count is the seam's exact pin of the one-controller structure, and the reset path's presence in the process is what makes the reset value of line 1 part of the synchronous controller rather than a loose record).

## Minimal fixture prerequisites

- A file-local non-first initial-state witness variant in `tests/fsm_lower_test.c` (the existing `FSM_WITNESS(NAME)` names `initial idle`, the first declared state): scenarios 1 (and 5's reset-path count) need a header naming the SECOND declared state (`initial run`, per-state index 1) so an always-first reset cannot pass. The established file-local macro pattern (and the (s2) identity witness `FSM_WITNESS_NONFIRST` precedent in tests/fsm_identity_test.c) makes this a file-local fixture, not a new fixture owner.
- Scenarios 2–4 reuse the existing `FSM_WITNESS(NAME)` fixture as-is (it carries the `done <= 1` action in `run`, the `if (start) goto run` and `if (!start) goto idle` guards, and the `done` output binding); no other new fixture or helper is required — `fl_parse`/`fl_unit`/`fl_drive` and the record collectors cover every line as written.
- No production-source change is part of any scenario: the authors register the discriminating sections; the behavior/stop implementation owners that the sections discriminate are the later owner depending on the accepted packet.
