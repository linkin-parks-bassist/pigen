The t8 guard-and-dependency test family (tests/rtl_lower_test.c section 16, family (7)) pins the escape this witness exposes: its guard is the two-atom conjunction (g == 1 AND f == 0, the expected-0 atom the negation) and its transfer carries five distinct (signal, role) uses, so the shared fire identity must be the memoized conjunction of the two lowered guard atoms plus the consumer-valid and producer-ready endpoint controls. The fire identity is a chain of PIGEN_RTL_EXPR_BINARY logical-AND nodes whose leaves are, in order: the g atom (expected 1) as a BINARY PIGEN_BINARY_EQUAL of the g payload OBJECT and the 1-bit-true BITS; the f atom (expected 0) as the f payload OBJECT directly (fire_atom returns the lowered condition unchanged for expected 0); c's valid and p's ready (both PIGEN_RTL_EXPR_INTEGER, the interned 1-bit-1 control, the same identity). No PIGEN_RTL_EXPR_UNARY node appears anywhere in the fire identity.

The guard-atom coverage probe (7.4) must re-derive each atom's lowered identity by the same path fire_atom uses: the atom's condition (a signal symbol read) lowers to the signal's published payload OBJECT (lower_expr's PIGEN_EXPR_SYMBOL case, src/rtl_lower.c:946), and the expected-1 atom wraps that OBJECT in the 1-bit-true PIGEN_BINARY_EQUAL. It must require that OBJECT identity (and, for the expected-1 atom, its equal wrapper) be reachable from BOTH the destination-update value set and the source-ready equation value set, and for the expected-0 atom require the OBJECT node is present and is NOT the first child of any positive PIGEN_BINARY_EQUAL. A negation-ignoring implementation (the f condition used positive) is rejected because its f OBJECT becomes the first child of an EQUAL, dropping the bare-OBJECT count to 0; a correct lowering passes.

Do NOT derive the atom's lowered identity from the const-expression memo: pigen_predicate_atom.condition is a pigen_expr_id (semantic.h:224) while lowered_expressions is keyed by pigen_const_expr_id.index (rtl_lower.h:39); a symbol read has no const-expr, so indexing the memo by the expr index is out of bounds (a coincidental or garbage identity, not the condition's lowered identity). This was the defect in the first draft of (7.4), which also probed for a PIGEN_RTL_EXPR_UNARY node that the correct lowering never produces, so a correct lowering would have been rejected and a negation-ignoring lowering would have passed.
