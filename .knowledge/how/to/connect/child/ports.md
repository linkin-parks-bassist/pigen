Child ports are parent endpoints. `producer a(clk, reset); consumer b(.clk(clk), .reset(reset), .i(a.o), .o(result));` connects siblings. Parent transfers read `a.o` or write `b.i`; named/anonymous fabrics route `a.o -> b.i`. Explicit wires remain supported. Output transfers remain explicit, e.g. `output uint[8] buf o`. Use static `input wire reset` for broadcast reset; unqualified input bit remains abstract.

Module declarations precede body resolution: sibling identities/omitted endpoints, static signal/slice input aliases, outputs, then general inputs. Forward references and later module definitions resolve. Control bindings do not count as payload bindings; dot lookup matches the payload name.

Typed endpoint_views represent static payload aliases and omitted outputs with explicit controls, without storage. Output slices publish observations while instances retain projections. Input endpoint_view_driven records sibling/transfer/fabric producers: lowering drives the original slice when marked, otherwise observes it. Undriven static projected expressions are continuously valid unless supplied valid qualifies them. Direct and exact projected aliases reuse the upstream output view when payload type/shape match. Projection equality strips groups/conversions and compares ordered constant bounds and bases recursively. Range, +: and -: forms normalize using the base packed direction; Signed constant coordinates preserve ascending/descending bit order. Shared views retain producer handshakes, consumer exclusivity and write protection; lowering uses the view's owning instance, independent of declaration order. `.o(b.i)` supports signal/slice bindings.

Symbolic controls map to parent RTL objects; selected controls use scalar proxies plus observation/drive equations. Omitted controls reuse declared payload_valid/payload_ready or get internal nets. Instance/dot/fabric emission shares controls. Read-only output-ready/input-valid expressions support manual handshakes; conflicting automatic consumers/producers diagnose. Raw-wire payload writes remain legal. Explicit parent-input controls, including scalar and selected signals, are read-only. Resolver ownership and endpoint lowering share pigen_lvalue_is_writable, so these bindings are observed without generated drivers. See how/are/lvalues/represented.md.

Computed inputs such as `.i(a.o + 8'd1)` become storage-free atomic transfers. Arithmetic joins sources; concatenations deduplicate reads; ternaries consume all referenced sources (how/does/an/atomic/transfer/fire.md). Explicit i_ready targets feed actual readiness to generated boundaries. Structural processes have no clock; cross-instance clock compatibility remains unaudited.

pigen_lower_rtl_endpoint_defaults zeros undriven generated input payload/valid and unconsumed output ready. Equations, updates, child connections and primitives count as drivers; borrowed controls retain ownership. Parent offers exclude their own destination readiness.

Ownership recognizes views/payload wires. Duplicate consumers and child/local conflicts diagnose; fabrics enforce elastic exclusivity across blocks. Static fanout/peek remain legal. Producer checks compare physical destinations of output views and automatically driven input views, including sibling, transfer and fabric writers. Distinct views cannot hide overlaps. Provably disjoint constant ranges/indices/indexed selections on static signals are legal; unknown relationships conflict. Buffered signals retain whole-token exclusivity. Partial consumer slices, unsupported/symbolic bounds, concatenations, direct local/ordinary-SV writes and transformed coordinates remain incomplete.

child-input-alias-ownership-test checks sibling/transfer/fabric writers, disjoint slices under independent stalls and overlapping input/output aliases. child-slice-ownership-test checks range/indexed slices and buffered exclusivity. child-port-endpoint-test covers payloads, controls, routing/introspection, neighboring bits and equivalent range/indexed aliases in either declaration order, negative, ascending/descending and multidimensional declarations, and duplicate-consumer/write errors. child-ready-manual-test and child-valid-manual-test cover manual/parent-input controls and automatic-owner conflicts.

Other expressions and arrays/generate scopes remain incomplete. Explicit-valid gate versus replacement policy remains unresolved. Specialization/count owners: how/does/specialization/reach/a/fixed/point.md and how/to/normalize/declaration/counts.md.
