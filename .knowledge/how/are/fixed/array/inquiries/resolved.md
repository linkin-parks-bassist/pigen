`$left`, `$right`, `$low`, `$high`, `$increment`, `$size`, `$dimensions` and `$unpacked_dimensions` resolve through analyze_array_query in src/expression_analysis.c. They return signed 32-bit four-state SV integers. Bound/size/increment functions accept a fixed expression/type operand and an optional scalar integral dimension, defaulting to 1; rank functions accept only the operand. Operand types are inspected without evaluating their data. CALL type metadata and inquiry_type share the `$bits` distinction (how/are/fixed-size/bit/inquiries/resolved.md).

Ordinary dimensions are numbered from 1: unpacked first, then packed after typedef expansion. Ordinary count-form unpacked bounds run from 0 to count-1; explicit ranges preserve direction. pigen_data_type_query_dimensions in data_type.h/data_type.c returns owned expanded packed dimensions; callers free them. Integer atoms/Pigen numerical types expose implicit vector bounds. Scalar bit/logic has rank zero; packed records have a vector dimension, including one-bit named records and direct anonymous struct type arguments. Outer packed dimensions remain separate.

`$left`/`$right` preserve endpoints; `$low`/`$high` sort them; `$size` returns cardinality. `$increment` is +1 for descending/equal bounds and -1 for ascending bounds. Zero, negative, out-of-range or X/Z dimension values return all-X integers. Bounds/cardinalities retain their low 32-bit integer pattern. Malformed calls, nonintegral/nonscalar dimensions and unresolved bounds reject.

Constant dimensions produce only result constants. Runtime dimensions build typed CASE_EQUAL comparisons and conditional selection over fixed results, retaining the dimension's full width and signedness. PIGEN_ANALYZED_CASE_VALUE preserves its local self-determined argument context (how/are/expression/call/arguments/sized.md). Only dimension expressions create runtime reads/consumption. Rank-zero queries retain dimension evaluation through an evaluated-value record even though their result is always X. Pure analysis publishes no semantic expressions/children/constraints.

Native collection inquiries use existing structural views, including child projections and slices. Scalar endpoints have structural rank zero; channel/field expressions expose payload dimensions. Native count/range directions follow their collection contract. Native wiring coordinates still require constant selectors. peek/valid/ready/accepts calls are supported as type operands or evaluated runtime dimensions with their ordinary observation semantics (how/are/handshake/calls/analyzed.md). Native endpoint typedefs are not packed data types and reject as type operands through inquiry_type (how/are/native/axi/type/aliases/represented.md). Dynamic arrays and arbitrary functions remain unsupported.
