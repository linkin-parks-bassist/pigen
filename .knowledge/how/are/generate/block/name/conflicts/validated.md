src/resolve.c validates structured generate source namespaces before selecting branches or publishing generated scopes. validate_generate_namespace builds a temporary name table for each parsed lexical source scope. The check visits selected and unselected branches and disabled loops; it does not evaluate their endpoint widths, parameter values or child hardware merely to inspect names.

A named block cannot share its name with a block from another generate construct or with a parsed parameter, genvar, typedef, signal declarator, child instance or typed procedural block label in that source scope. Alternatives of one conditional construct may share a name. Directly nested if/case selections share their outer conditional's family, allowing an if/else-if or mixed if/case chain to use one block label. Begin/end blocks create separate namespace tables. Generate-region wrappers are transparent, so separate regions in one module do not hide conflicts.

A conditional with an unbraced loop body creates an anonymous outer namespace; the loop's label belongs inside it. A loop iteration introduces its own scope even when its unbraced body is another generate construct. Its implicit iterator parameter participates in the iteration namespace. A loop-body block name belongs to the enclosing namespace; its contents belong to the iteration. Separate outer scopes may reuse the same inner labels. validate_procedural_namespace_names registers typed combinational labels in their enclosing source namespace, stopping at block/loop scope boundaries; private block locals do not leak into generate namespace checks. The tables are freed on success and failure. The existing semantic generate-scope constructor still checks selected scope identities independently.

This implements the parsed structured portion of IEEE 1800-2017 section 27.5's source-name rule ([IEEE text](https://fpga.mit.edu/6205/_static/F25/documentation/1800-2017.pdf)). Ordinary retained/opaque declarations and generate constructs are not interpreted by this pass; auditing their interaction with flattened native scopes remains work. Automatic external names are a separate concern (what/are/automatic/generate/block/names.md).

Evidence: tests/named_procedural_block_test.py rejects procedural/generate label collisions in both declaration orders and with selected/unselected native branches. tests/generate_semantic_test.c covers disabled duplicates, valid repeated conditional labels, directly nested case alternatives, conflicts inside unselected parents, parameter/signal conflicts, loop/block conflicts, separate lexical scopes, unbraced loop isolation, conditional-loop scope parentage and implicit-iterator conflicts. The focused semantic test passes under ASan/UBSan. Full make verify passes native array and standard-core simulations. tests/native_array_test.py rejects hidden block, port and parameter conflicts, nested disabled conflicts and cross-region conflicts for all three AXI families, preserving existing output on failure. A conditional-loop negative confirms that its nested loop label cannot leak into module lookup; an independent all-family pin scoreboard checks parameterized children beneath the anonymous conditional scope under stalls/reset.
