Procedural case operands use an explicit shared comparison context while retaining intrinsic Pigen numerical operations. pigen_resolve_case_expression in expression_resolve.c resolves integral scalar selectors and labels in the CASE literal domain; pigen_resolve_case_context applies the maximum operand width and signedness only when every operand is signed. src/resolve.c:resolve_case_operands supplies the shared selector/label context for combinational and clocked cases (how/are/clocked/case/statements/represented.md). Combinational buffered observations require peek. Clocked selectors and labels may read buffered tokens directly; those reads join the enclosing transfer guard dependencies and deduplicate with payload reads (how/does/an/atomic/transfer/fire.md). The consuming-selector integration checks are owned by how/are/clocked/case/statements/represented.md. Resolution failures restore expression arenas.

For native SV integral operations, data_type.c owns case binary/unary rules and expression_resolve.c propagates width/sign context through arithmetic, bitwise operations and conditional alternatives. Shift/power counts and concatenation children remain self-determined. Comparisons normalize their operands in their own context. Logical AND/OR/NOT normalize vector operands through typed reduction-OR before applying the logical operator; case_vector_truth preserves four-state truth and avoids implicit vector-width lint diagnostics. Sign reinterpretation occurs before padding. Four-state values remain four-state unless an explicit cast converts them.

Explicit casts carry is_context_cast even when otherwise identity; their boundary width is preserved. Unbased '0/'1/'x/'z literals carry unbased_fill and expand under the owning context. Sized based question-mark digits parse as Z, including casez labels. Assignment fill contexts, packed selections and ternary controls use how/are/assignment/fill/literals/resolved.md; supported intrinsic call arguments have independent sizing boundaries (how/are/expression/call/arguments/sized.md), while arbitrary function/task integration remains work. Constant packed selectors/labels can use the bit-level selection evaluator (how/are/constant/packed/selections/evaluated.md). Combinational controls reuse the self-context machinery (how/are/combinational/controls/resolved.md); retained SV is unchanged.

Concrete Pigen int/uint subtrees retain lossless family arithmetic. Decimal-only constant syntax paired with a numerical operand resolves in the Pigen domain; numerical typed casts without fills also resolve operands in that domain. Fill-containing numerical cast operands use CASE context; the explicit cast still owns conversion. Pure constant recipe context is owned by how/are/analyzed/constants/contextualized.md. This prevents SV decimal32 sizing from changing uint8+1 or uint64'(2147483647+1). Native typed and size casts keep CASE domain. Pure analysis and direct intrinsic-containing resolution share these rules. Explicit four-to-two conversions are owned by how/are/four-state/values/converted/to/two-state/types.md.

Evidence: include/pigen/expression_analysis.h and semantic.h carry CASE domain, unbased_fill and cast-boundary metadata; expression.c classifies decimal-only syntax without substitution. tests/cores/continuous_intrinsics* checks overflow, signed shifts, wider labels, casts, fills, comparisons, concatenations, numerical promotion and peek against independent references.
