src/expression_analysis.c resolves named generate paths against selected pigen_semantic_generate_scope records. generate_scope_reference selects an existing lexical scope; scoped_symbol_reference then uses pigen_symbol_lookup_local to find a local binding and follow canonical aliases. A path such as rows[-2].columns[1].child.m reaches the generated instance and its ordinary parent endpoint views. Procedural block symbols share this path traversal (how/are/named/procedural/blocks/resolved.md). No scope becomes a runtime value, and emitted RTL names never participate in lookup.

For a leading name, search starts at the current lexical scope and walks parents. A local symbol shadows a generated-scope name. Once a matching named scope collection is found, a missing/wrong index cannot fall through to an outer collection. Iteration scopes require one known signed constant coordinate matching a selected iteration; scalar named blocks require no index. Nested path components select direct child scopes. The final member must have a local binding in the selected scope rather than borrowing an enclosing declaration. Unselected branches have no addressable scope. Scope-path recursion is bounded at 128 levels.

Protocol scalar/collection reference resolution shares this lookup with expression analysis. Generated child native ports reuse canonical endpoint/array/instance identities, normal roles/contracts, timing and ownership. Scope indices are consumed during scope selection; later native endpoint-array indices retain their separate rank/coordinate semantics. Generic static signals, local constants/genvars and ordinary child ports resolve through the same scoped symbol identities. Typed constants remain constant DAGs, and buffered ports retain endpoint views and handshake ownership.

Fabric endpoint parsing accepts repeated member/index suffixes and preserves a full expression identity. The legacy instance/port pair remains only a compatible simple path; complex native paths resolve from expressions. Separate generated regions can instantiate and connect the same endpoints; examples/native_axi_generated.pigen demonstrates native_axis_named_bank. Named paths work in parent transfers, direct/routed fabrics, child bindings and whole child-array bindings without backend scope reconstruction.

Evidence: tests/native_array_test.py independently checks all AXI families through nested signed-coordinate paths to generated children, selected named blocks and child arrays; module/whole-array bindings; scoped constant/genvar observations; and mixed ordinary buffered endpoints under stalls and queued reset. Negatives reject runtime/out-of-range/missing/extra indices, absent/unselected blocks, scalar-block indexing, enclosing-member fallback and duplicate owners through equivalent index expressions. tests/generated_instance_test.c uses a relative named genvar path in child parameter overrides and exercises it under sanitizers.

This supports named scopes in the current module's structured generate tree. Automatic genblk identifiers are external-interface metadata, not authored hierarchical names (what/are/automatic/generate/block/names.md). Cross-module internal hierarchy and broader retained-SV contexts remain outside these witnesses (how/are/structured/generate/scopes/elaborated.md).
