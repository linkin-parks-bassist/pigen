Ordinary structured-module layouts emit parsed parameter nodes as localparams. Semantically specialized child modules instead lower their resolved module-scope parameters to RTL PARAMETER objects, each with type, final name and initial_value expression. The renderer emits typed localparams from those records and output suppresses duplicate source parameter nodes (how/are/generated/child/parameters/specialized.md). This preserves names used by retained initial/ordinary-SV items; header parameters must survive when retained code references them. Ordinary SV type spellings are retained, and explicit Pigen int[n]/uint[n]/bit[n] parameter types render as signed/unsigned packed bit types with descending count ranges. Macro-expanded initializers use the expanded token text. Module-level body parameter declarations are emitted once from their parameter nodes; src/syntax.c no longer also retains a duplicate raw declaration.

Native package parameters own constant semantic objects in package scopes, with no hardware module. Output preserves their names as localparams; parser cursors consume authored comma/semicolon separators so top-level rendering emits each declaration once (how/are/native/axi/package/types/represented.md).

Selected structured generate parameters are lexical semantic constants whose values lower through the constant owner; their source templates are not emitted as module-level localparams. Generated retained-SV contexts still require integration (how/are/structured/generate/scopes/elaborated.md). Procedural grouped constants inherit the declaration's explicit type and resolve in lexical source order (how/are/combinational/block/local/declarations/represented.md); this does not establish module/header continuation typing.

src/resolve.c:add_parameter resolves a declared type before its default value. Typed defaults and typed child overrides use pigen_resolve_assignment_value in their respective lexical scopes; publication requires a constant identity afterward. Untyped defaults retain resolve_constant and value-inferred types. Bare SV int parameters without a width argument use signed 32-bit two-state storage, respecting an explicit unsigned qualifier. Invalid types and nonconstant or incompatible values reject before parameter publication. add_parameter preserves expression diagnostics, including ambiguous imports, rather than replacing them with a generic constant error. Successful bare-SV-int fallback clears its recovered type diagnostic.

Direct and compound unbased fills therefore receive the declared packed width through the existing assignment owner. A procedural localparam logic[7:0] FIRST={4'h5,4'ha}, SECOND=FIRST^'1 now resolves SECOND as 8'ha5. tests/static_local_initializer_test.py compares compound fills, 64-bit masks, narrowing, signed shifts and X/Z-to-two-state conversion with native SV over 1,024 inputs, and checks independently specialized 32/64-bit query/mask constants for all three native AXI families. A typed runtime-token default rejects with output preservation. Nonfill comparison wraparound and carry-derived declaration widths also match native SV through the shared assignment context (how/are/expressions/resolved.md). This covers these default expressions; broader expression sizing and aggregate forms still require the compatibility audit.

The retained-parameters case in tests/cores/run.py compiles/lints/simulates macro-valued integer parameters, signed int[9], unsigned uint[8], bit[4], a dependent int[10] localparam and a native transfer, checking values and $bits. Core parameter guards additionally exercise these names in retained initial blocks; six invalid configurations terminate with explicit fatal diagnostics. This evidence does not establish arbitrary type parameters or all aggregate parameter forms.
