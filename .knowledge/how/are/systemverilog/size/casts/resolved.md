SystemVerilog size casts resize an integral operand while preserving its self-determined signedness and two-state/four-state character. Literal widths (`12'(value)`), parameter names (`WIDTH'(value)`) and parenthesized constant expressions (`(WIDTH+1)'(value)`) use the same target/conversion owner. Widths must resolve to positive integral constants within the active generated-bit policy. Runtime, zero, negative, unknown and excessive widths reject. This follows IEEE 1800-2017 §6.24.1 ([standard](https://fpga.mit.edu/6205/_static/F25/documentation/1800-2017.pdf)), checked against the cached text.

src/lexer.c keeps apostrophes in numeric tokens for based-literal prefixes and unbased one-bit literals; size-cast apostrophes remain separate punctuation, including when comments separate the cast tokens. src/expression.c represents explicit expression sizes as PIGEN_SYNTAX_EXPR_CAST with as.cast.is_size, size and value; type is invalid. Existing type casts retain type/value with is_size false. A simple identifier cast remains syntactically ambiguous: lexical parameter symbols supply widths, while typedefs use ordinary type lookup. Every cast retains source provenance.

src/type_resolve.c:pigen_resolve_cast_type is shared by temporary expression analysis and direct intrinsic resolution. Explicit sizes use constant-only SystemVerilog expression analysis with the supplied width policy; named parameters use canonical symbol constants through shared type-symbol lookup, including qualified/imported package parameters at the source position (how/are/native/axi/package/imports/resolved.md). Width evaluation must produce a representable positive integer. The operand must be integral or an exact Pigen integer. Implicit raw-vector sign defaults unsigned; exact Pigen integers use signed size-cast results. Named type casts retain pigen_resolve_type. Contextual record casts still obtain their target schema before resolving their value; size casts cannot provide a record schema.

include/pigen/data_type.h and src/data_type.c own pigen_data_type_sized_integral(model,width,sign,state), which interns a bit or logic vector of the requested signedness and descending packed range, or the scalar representation for width one. Invalid width/sign/state rejects. pigen_data_type_sized_logic remains a four-state wrapper. Native operand context uses the greater intrinsic/cast width before explicit conversion, preserving operand common signedness and intermediate X/Z until the final cast. Thus 8'(wide64>>56) shifts at 64 bits before truncating. Exact Pigen integers retain their mathematical value until conversion; no nonexistent packed width is queried. Nested casts preserve their separate widths (how/are/assignment/fill/literals/resolved.md). Explicit conversion and existing terminal emission then implement resizing; no raw SV cast text bypasses semantic typing. Expression failure retains the existing no-partial-publication guarantee.
