Declarations belong to lexical scopes and introduce stable typed symbol identities. Typed runtime declarations denote signals, including ordinary nets/variables. Canonical object-bearing symbols retain the object's symbol ID; separately declared genvars are elaboration-only GENVAR markers without values/signals. Identifier occurrences resolve to one canonical symbol. Resolved-name-only states are forbidden.

Parentage determines nearest-declaration lookup, including nested combinational blocks, stage/pipeline scopes and selected generate scopes. Duplicate local declarations reject at introducing spans. pigen_symbol_declare can report a shadowed outer symbol; a nearer declaration governs lookup. Iteration genvar bindings are immutable local parameters in distinct scopes (how/are/external/genvar/declarations/elaborated.md). Generate scope/item records distinguish repeated source templates (how/are/structured/generate/scopes/elaborated.md). Generated FSM registers remain distinct in selected iteration scopes (how/are/generated/fsms/resolved.md).

A procedural lexical alias binds another specialization's scope to the same canonical static declaration. pigen_symbol.alias_of is INVALID for ordinary declarations. pigen_symbol_bind_procedural_alias accepts only signals, parameters, packed typedefs and native protocol typedefs whose source and destination scopes share a procedural root. Automatic signal targets reject. It creates a lexical entry with a canonical target and no duplicate object. pigen_symbol_lookup, pigen_symbol_lookup_text and direct-only pigen_symbol_lookup_local follow aliases to the canonical ID, with bounded traversal. Duplicate-name checks still inspect actual local bindings. Direct object accessors keep their canonical symbol/object ownership checks; the raw alias ID cannot masquerade as the signal owner.

Native collection foreach uses these aliases to preserve static body declarations across specialized coordinate branches and nested loops (how/are/native/axi/collection/foreach/loops/resolved.md). The cache is keyed by process and declaration syntax. Automatic variables bypass this static cache and resolve per-specialization entry initializers (how/are/automatic/procedural/initializers/represented.md). Ordinary generate iterations and separate processes do not share declarations through this mechanism.

PIGEN_SYMBOL_PROCEDURAL_SCOPE binds a named block to a child procedural scope through pigen_symbol_bind_procedural_scope. Qualified paths require a local binding in that child; canonical aliases need not be owned by that same specialization (how/are/named/procedural/blocks/resolved.md).

Package import records preserve canonical symbols without declaring copied objects. PIGEN_SYMBOL_RETAINED_SUBROUTINE represents ordinary package function/task names; RETAINED_LOCAL represents lexical body declarations. Both have invalid DATA/hardware identities. Retained local scopes participate in normal import lookup without runtime objects (how/are/retained/package/namespace/uses/resolved.md). Lookup APIs stay pure, including source-point lookup_at/lookup_text_at; resolve_at/resolve_text_at activate source-point wildcard bindings; resolve_call_text_at uses scope-end bound names and source-point candidates for retained calls (how/are/retained/package/calls/bound.md). Local declarations precede unbound candidates, while explicit/activated imports prevent conflicting declarations. Direct-member lookup excludes unexported imports (how/are/native/axi/package/imports/resolved.md). The semantic pigen_export_package API creates local canonical aliases for actual imported declarations, distinct from procedural lifetime aliases; structured exports preserve source-order binding (how/are/native/axi/package/exports/represented.md).

Named generate paths select existing scopes and directly declared symbols (how/are/named/generate/scope/paths/resolved.md). Generated RTL spellings are assigned after semantic resolution and cannot affect lookup. Generated local signal/channel names include lexical scope identities. Structural type equality and object identity never depend on spelling. Passes consume predecessor records and do not inspect opaque text for hidden dependencies.
