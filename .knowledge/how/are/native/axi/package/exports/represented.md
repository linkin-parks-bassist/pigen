Structured packages support `export pkg::name;`, comma-separated entries, `export pkg::*;` and `export *::*;`. Exported AXI types, DATA schemas and constants retain original canonical identities across qualified uses, imports, parameterized children, arrays and fabrics. Imports: how/are/native/axi/package/imports/resolved.md.

syntax.h EXPORT nodes reuse package_import tokens/flags. syntax.c:parse_import parses both namespace declarations; structured_package_at selects semantic package sources. Named exports immediately contribute conservative type-classification facts; exported_package_facts propagates eligible package facts at closure. specialize.c carries matching exported-name hints, including aliases declared between an export and a later import. Hints never supply semantic contracts. Exported-name fan-out grows its hint arena dynamically.

resolve.c:resolve_package_exports runs during ordered package resolution. Named exports activate at their authored point. A matching later import can supply that candidate, but only the named declaration becomes visible early. Dependent declarations therefore resolve before the later import without exposing unrelated names. Missing routes/members and conflicts reject. Wildcard directives finalize after the package's value uses and deferred retained calls are bound; unused candidates do not become public.

semantic.h/semantic.c:pigen_export_package requires a matching import route. Named exports use the explicit-import owner to activate a candidate. Wildcards materialize only explicit/activated imports visible at the supplied position, restricted to the selected package when applicable. Invalid package ID with wildcard=1 denotes all imported packages. Repeated exports are idempotent.

Exports create package-local alias symbols targeting original canonical declarations, with no new storage or copied type/protocol/constant objects. Package-member and wildcard-import lookup see those aliases. Multiple exported paths to one declaration stay unambiguous. Procedural alias lifetime rules remain separate (how/are/scopes/and/symbol/bindings/represented.md).

output.c suppresses explicit native-type exports. Ordinary named exports publish an explicit import at the authored reference point; export statements render after package items, before the closing wrapper. This preserves early references and accommodates Icarus's rejection of exports before imports. Wildcard imports retain actual bound ordinary names explicitly when lowering erases activating references. Actual ordinary routine imports also publish canonically after the package header, before candidate wildcards, so backend export lookup preserves their identities (how/are/retained/package/calls/bound.md). DATA/constant positions retain their source-order behavior. Terminal emission stays semantic-free.

Basis: IEEE 1800-2017 §26.6 permits exports before imports, limits wildcard exports to actual imports, treats named exports as references and preserves identity through multiple paths ([standard](https://fpga.mit.edu/6205/_static/F25/documentation/1800-2017.pdf)). Verilator accepts the independent ordinary-SV early-reference oracle.
