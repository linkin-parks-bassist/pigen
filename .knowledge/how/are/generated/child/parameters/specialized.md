src/resolve.c evaluates selected PARAMETER_CONNECTION expressions in the instance's lexical scope, including immutable genvars and local constants. Named and positional overrides stay separate from data ports. Mixed forms, unknown/non-overridable names, excess positions, duplicates (including empty overrides) and runtime values reject. Empty entries retain defaults. Declared typed defaults and overrides use the ordinary assignment-value resolver after resolving their declared type; dependent defaults resolve in the fresh child scope after preceding parameter declarations. Each published value must remain constant (how/are/parameters/preserved/for/retained/systemverilog.md).

Each selected specialization owns a semantic module, symbol and compilation-child scope while retaining its template syntax. pigen_semantic_module records specialization_of and specialization_parent IDs. A synthetic name/declaration span preserves symbol-constructor invariants without changing source templates or broadening name containment. Reentrant declaration resolution installs override identities only for matching parameter syntax, then restores the caller's scope/context. Specialized bodies enter the normal module-resolution queue. Native protocols, clocks, ownership and hierarchy checks apply to the resulting types and endpoints.

Repeated template/parameter values along specialization ancestry diagnose recursive instantiation. Constant-ID equality and signed/unsigned 64-bit evaluation recognize equal values; general wide-expression equivalence remains unaudited. The hierarchy-depth limit is 256. This bounds recursive elaboration without host-stack recursion. Specializations currently remain distinct per selected instance rather than being shared by configuration.

Generated parameter instances bypass the earlier source-token specialization pass. All native child calls, including module-root calls and typed standalone fabrics, defer to the same typed specialization path, preserving parameter types and transitive bindings until semantic scopes exist. Module-root ordinary source specialization remains a separate path (how/does/specialization/reach/a/fixed/point.md).

RTL lowering publishes specialized children as generic owned module instances. Specialized module parameters become PARAMETER objects carrying resolved type/name/initial_value expressions, so retained SV names observe overridden values. Output appends specialized module layouts from the template's children and finished records; it suppresses duplicate source parameter/instance emission. The terminal renderer consumes these records without semantic inference. Storage DEPTH is evaluated as a positive constant and converted to its primitive's signed 32-bit int interface; values above INT32_MAX reject.

Evidence: tests/generated_instance_test.c checks iteration-specific values, template/parent identities and lowered parameter objects, including unselected suppression. tests/native_array_test.py independently scores all-family transport and static parameter observations for named/positional overrides, skipped dependent defaults, typed narrowing, nested native child propagation and distinct per-lane FIFO depths under stalls/reset. Negative cases check invalid overrides, width contracts, recursion and output preservation. examples/native_axi_generated.pigen includes a configured lane bank. Broader retained-SV/generate contexts and wide-constant cycle equivalence remain outside these witnesses.
