Packed replication requires a known nonnegative integral count in the Pigen literal domain, subject to the caller's maximum_generated_bits and checked allocation arithmetic. Positive counts analyze the body once and repeat references in a typed CONCATENATION. Pure analysis publishes no semantic expressions; its constant recipes preserve each retained child's original type after self-context.

Zero-count replication is permitted inside a concatenation or replication body with a positive-sized peer. Parentheses around an empty field are transparent; an extra concatenation establishes its own positive-size requirement. Standalone zero, all-empty/nested-all-empty concatenations, unknown/negative/runtime counts, malformed operands and unsupported calls reject. Known X/Z ignored payload bits are legal. Unpacked endpoint assignment-pattern replication retains a separate positive-count contract (how/are/native/axi/collection/assignment/patterns/resolved.md).

Constant-only analysis uses constant_empty_replication to validate all ignored scalar constant operands before removing their bits. It recursively validates nested empty fields and builds dense retained vectors without a zero-width data type or synthetic zero bit. Unknown names and mutable ignored operands are invalid in constant expressions. Pure analysis and published constant materialization agree in Pigen/SV/CASE literal domains.

Nonconstant analysis uses analyze_runtime_sequence to resolve every field without publication, temporarily representing an empty field by its positive-sized body plus an empty flag. It attaches ignored runs before/after their nearest value using PIGEN_ANALYZED_EVALUATED_VALUE. Normal positive fields retain their order and widths; no empty scalar escapes. The postorder materializer builds semantic EVALUATED_VALUE records that retain reads through use analysis, aliases, RTL and emission (how/are/evaluated/values/represented.md). Ordinary runtime operands use this analyzed path. Intrinsic/fill contexts retain resolve_runtime_sequence's direct path and local argument sizing; these contexts do not broaden the generic analyzer's existing call grammar.

[IEEE 1800-2017, section 11.4.12.1](https://fpga.mit.edu/6205/_static/F25/documentation/1800-2017.pdf) requires operand evaluation even at count zero. Buffered ignored reads therefore retain transfer dependencies, repeated reads deduplicate, and peek remains non-consuming. Typed user-function/impure-effect integration remains separate work; this support does not claim those calls.
