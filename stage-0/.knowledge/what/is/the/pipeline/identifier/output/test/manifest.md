tests/pipeline_output_test.c is the discriminating test contract for pipeline step (a): the pipeline identifier as a module-scope buf output packet identity (plan: what/is/the/plan.md step (a); spec: what/is/the/spec.md, what/does/pipeline/yield/mean.md; gates: what/are/the/remaining/architecture/migration/gates.md). It pins the owner include/pigen/pipeline_identity.h + src/pipeline_identity.c (pigen_pipeline_identifier_establish / pigen_pipeline_identifier_of). It is a four-section manifest, one `make pipeline-output-test T=<section>` entry per section in tests/contracts.json (four entries); the Makefile target compiles with the exact CFLAGS (-std=c17 -Wall -Wextra -Wpedantic -Werror -O2 -Iinclude) against src/pipeline_identity.c plus the semantic and syntax owners.

Pinned law: the identifier names exactly one module-scope signal whose transfer type is buf and whose direction is a module output, whose data type is the outgoing packet aggregate (the concatenation, in source order, of the fields the final yield reads, built as an unsigned sized vector of the summed packed widths), bound to a module-scope symbol recoverable through the module's symbol/signal set and pigen_symbol_signal, with symbol and signal spans anchored at the identifier's original token span. Every field is a buf (omission canonical, explicit buf equivalent, one dialect) and the output packet carries that same buf.

Witnesses are built through the owner APIs: the source is parsed to obtain the PIGEN_SYNTAX_PIPELINE node, identifier span, field declarations and clock span, and the semantic model (module, scope, clock signal/domain, process) is built directly via the semantic owners. The witness cannot lower through pigen_resolve_semantics (the resolver rejects a clocked process containing a pipeline), so the model is constructed directly and the owner's establish/accessor entries are driven on top.

Sections (all green on master):
- output-identity: a single 8-bit field yielded; the identifier resolves to exactly one module-scope signal with transfer type buf AND direction a module output. Dropping the output direction or a non-buf transfer type fails.
- outgoing-packet-type: the established signal's data type is the outgoing packet aggregate, pinned by packed width to the YIELD-SELECTED field set (selected by the field NAMES the yield expression references), not the all-fields sum. Four witnesses: a single 8-bit field gives 8; two fields {8, 16} with `yield {x, y}` gives 24; two fields with `yield x;` (a proper subset) pins 8, not the 24-bit sum; and two fields with `yield y;` — the NON-PREFIX witness — pins 16, the yielded field being the SECOND (16-bit) one. The first three each select a PREFIX of declaration order, so a POSITION-BASED first-N builder (N = fields the yield references) would give identical widths for all of them; the fourth discriminates, because first-N with N=1 would select the first field x and establish 8 bits (failing the 16-bit pin) while name-based selection reads y and establishes 16 bits — 16 != 8 is the discriminator. In the subset and non-prefix witnesses po_outgoing_width is deliberately not the oracle (it sums every declaration, 24); the 24-bit escape (po_outgoing_width == 24) is asserted to document why the width-only pin was previously blind.
- module-scope-binding: the identifier is bound to a module-scope symbol (the module scope whose parent is the compilation scope, not a stage-/pipeline-local child), recoverable via pigen_symbol_signal and present in the module's signal set, with symbol and signal spans anchored at the identifier's original span.
- buf-field-consistency: every field is a buf and the output packet's transfer type is that same buf, pinned from an omitted-buf single field and an omitted+explicit-buf pair.

Member ORDER of the aggregate is not pinned here: the aggregate is a width-keyed sized vector, so field-to-bit member order is unobservable through this manifest and is owned by the step-(c) lowering's emitted-SV / golden witness (does/the/concatenation/data/type/keying/keep/member/order.md), not by this contract. This contract pins field-set / aggregate membership. The prior pipeline-identity-test (shape/field-buf/scope/yield) stays green; the manifest carries the four entries. No production switch, second dialect, fallback or prototype-parity.
