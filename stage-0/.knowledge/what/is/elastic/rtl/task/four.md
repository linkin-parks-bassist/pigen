Implementation (src/rtl_name.c): pigen_rtl_assign_names runs one module-local pass. Phase 1 validates every request before any arena mutation (model non-NULL, non-empty request set, every kind in SOURCE..TEMPORARY, every SOURCE span checked by pigen_source_span_valid) so a single bad request returns an invalid id and publishes nothing. Phase 2 resolves each request to a name identity without touching the arena: a request reuses a published name with the same identity (role plus origin span), else reuses the slot an earlier request in this call claimed, else takes a fresh arena slot. Phase 3 publishes only the genuinely new names in request order, SOURCE roles copying the checked span's provenance spelling via pigen_source_span_text + pigen_copy_range (model-owned, NUL-terminated, never a source pointer) and internal roles taking a role stem (payload/valid/ready/instance/temporary) with a deterministic numeric suffix only on collision. The suffix loop starts candidate=1, so the first free suffix is _1 (payload_1, payload_2, ...); the comment at src/rtl_name.c:94-97 states this behavior (first free suffix _1, the loop as the collision backstop whose _2-and-higher branch is unreachable under the verified identity model). The publish is half-open: a failing assignment leaves the names arena exactly as before, and staged text cannot leak because pigen_resize/pigen_copy_range exit on OOM. Repeat assignment of the same request set reuses existing names (identical terminal text, no duplicate growth), and two independently built models from the same request set yield byte-identical terminal text. pigen_rtl_name_get(model, name) returns the terminal record for a valid in-range id and NULL for a NULL model, an invalid id, or an out-of-range id.

Identity contract (verified against src/rtl_name.c): name identity is the role plus the origin span (source index and half-open byte range), per same_identity at src/rtl_name.c:39-47; request order is not part of identity. A published record or an in-call request is reused whenever identities match (requests_match, :56-60; in-call dedup, :186-195). Consequences: SOURCE requests use distinct checked spans, so they never share an identity; synthetic internal roles carry an invalid span, so each internal role has exactly one identity, and identical internal requests (e.g. two PIGEN_RTL_NAME_PAYLOAD with an invalid span) dedup to a single name (name_count grows by one, the second request reuses the first's id). The unique_name suffix loop therefore sees at most one fresh request per stem per call: a stem colliding with a copied SOURCE spelling takes _1, and the _2 and higher branch is unreachable under the current identity model. A same-stem collision test that expected a distinct _2 suffix for two distinct-span PAYLOAD requests was false on two counts: the requests shared one identity (dedup, not collision), and no request set under this model can reach _2.
