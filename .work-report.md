## The hard algorithm: helper unification

The four packets each carried the two shared probe helpers with INCOMPATIBLE
`rtest_collect_exprs` signatures (t8-fire-identity / t8-guard: 6-arg
int-return; t8-ownership: 3-arg pointer-return) plus an identical-signature
`rtest_shares_nonconst` defined in two of them, and t8-guard carried a
third, section-local helper `rtest_count_reachable_kind`. A naive file union
redefines the helpers and fails under -Werror.

Resolved by placing ONE file-local helper pair (plus the guard-local
counter) once at the top of the file, before `main()`:

- `static int rtest_collect_exprs(const pigen_rtl_model *, pigen_rtl_expr_id,
  int *seen, pigen_rtl_expr_id *out, size_t out_capacity, size_t *out_count)`
  - the 6-arg identity-based reachable-set walk (t8-fire-identity / t8-guard
  form), which t8-guard's call sites already match and which the shared
  counter calls internally.
- `static int rtest_shares_nonconst(const pigen_rtl_model *, pigen_rtl_expr_id,
  pigen_rtl_expr_id)` - the one 3-arg shared-identity detector; all four
  sections already call it with the same signature, so no call site changed.
- `static int rtest_count_reachable_kind(...)` - the guard section's own
  kind counter, kept as its file-local static (used only by t8-guard).

t8-ownership's section body calls only `rtest_shares_nonconst` (never the
3-arg pointer `rtest_collect_exprs` directly), so unifying on the 6-arg
`rtest_collect_exprs` and the single `rtest_shares_nonconst` is sufficient and
requires no ownership call-site relocation. Detection semantics are preserved:
identity-based reachable-set walk through the model's child links, reporting a
shared identity whose record kind is not `PIGEN_RTL_EXPR_INTEGER`.
