## The real blocker: the committed emitter is broken (3 defects in e97d477)
A faithful local harness (public owner APIs only, mirroring the hidden
t10-golden witness from packet 7342b25, with the re-scoped instance line) was
built and run against the committed `src/sv_emit.c`. The committed emitter CANNOT
produce the re-scoped golden; three defects were found, the first a hard crash.

### Defect 1 (hard crash / OOM): infinite padding loop, src/sv_emit.c:307-308
```
buf_append_str(b, direction);
while (strlen(direction) < 6)
    buf_append_str(b, " ");
```
The loop pads the direction to six columns but appends spaces to the buffer while
testing the CONSTANT `strlen(direction)`. For `input` (5) and `inout` (5) the
condition is always true, so it appends spaces until the buffer doubles to OOM
(verified: buffer grew to 134217729 bytes, then SIGKILL). ANY module with an
`input` or `inout` port never finishes emitting. The golden's first port `a` is
`input`, so the whole-design emit OOMs.
Correct form (verified in scratch):
```
size_t dlen = strlen(direction);
buf_append_str(b, direction);
for (size_t pad = dlen; pad < 6; pad++)
    buf_append_str(b, " ");
```

### Defect 2 (logic failure): top-level walk has no nested-range skip,
src/sv_emit.c:579-598
```
for (i = 0; i < layout->item_count; i++) {
    ...
    switch (item->kind) {
    case PIGEN_OUTPUT_OPAQUE: ...
    case PIGEN_OUTPUT_MODULE: ...
    default: goto fail;   /* "structured item outside a module" */
    }
}
```
The ordered output model (Task 9 build walk, src/output.c) is a FLAT array whose
`item_count` includes each module's nested children (the module's `layout` range
points into the same array; t9-nesting pins exactly this). The top-level walk
iterates every item in `item_count`, so the first nested child (a structured
item) hits `default` -> `goto fail`. ANY module with children fails to emit. The
hidden t10-golden builds `item_count = 13` (opaque, module, 10 nested children,
opaque) and expects `ret == 0`; as committed it returns -1. A top-level walk must
skip items inside a module's nested range (rendered by emit_module).

### Defect 3 (rendering): signal declaration / width / comma are wrong
With Defects 1 and 2 fixed in a scratch copy, the golden still does not match.
Rendered vs expected:
```
got :  input logic  a,            want:  input  logic [7:0] a,
got :  outputlogic  b,            want:  output logic [7:0] b,
got :  input  clk,                want:  input  logic clk
got :  logic  c;                  want:  logic [7:0] c;
got :    assign d = {c,e};        want:  assign d = {c, e};
```
So in addition: (a) the `logic` keyword is placed before the range and the
range `[7:0]` is dropped entirely (emit_object / emit_range, src/sv_emit.c:273-324);
(b) the port-header comma rule is wrong — the last port must take no comma and
the newline placement differs; (c) the concatenation join is `{c,e}` not
`{c, e}` (render_children join, src/sv_emit.c:~681-691).
