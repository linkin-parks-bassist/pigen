## What was implemented

The net/variable constant controls (COMBINATIONAL_NET / PROCEDURAL_VARIABLE valid
and ready) are implemented in `src/rtl_lower.c` only, exactly per the brief:

- New file-local `control_constant(lowering, constant)`: builds the 1-bit logic
  data type through the owner (`pigen_data_type_sized_logic`), lowers it through
  the existing `pigen_lower_rtl_type` memo, interns the descriptor 0/1 value as a
  semantic constant-expression identity via `pigen_const_expr_intern_integer`
  (owner memoizes by value, so the two valid constants — both 1 — share one
  identity while the ready constants differ), then lowers that identity through
  the existing expression memo so it publishes exactly once per identity. The
  1-bit literal is published via `pigen_rtl_expr_add_literal` with `bit_count=1`
  (the `pigen_rtl_expr_add_integer` uint64_t convenience constructor hardcodes a
  64-bit literal, which section 10 rejects). The control is an expression
  identity carrying NO published object.
- `net_variable_endpoints` now takes the descriptor `valid_constant` /
  `ready_constant` and publishes them into the endpoints record's valid/ready
  expression fields.
- The dispatch passes `descriptor->valid_constant` / `descriptor->ready_constant`
  (the source type descriptor's fields, already fetched for realization
  selection) — no `PIGEN_TRANSFER_TYPE_*` source-enum spelling is added to
  `src/rtl_lower.c`.

The payload object behavior (section 9) and the endpoint map / dispatch of
`pigen_lower_rtl_module_declarations` are unchanged. No BOUNDARY, storage, or
Makefile/test/contract changes.

## Blocker: section 9 frozen assertion is unsatisfiable by any correct implementation

Section 9 (`t6-net-variable-payload`, `tests/rtl_lower_test.c:1985`) has a
`distinct` assertion that compares the payload OBJECT-arena index against the
valid/ready EXPRESSION-arena index as if they were one namespace:

    wire_endpoints->payload.index != wire_endpoints->valid.index  // object idx vs expr idx
    ... (same for ready, reg, and payload-vs-payload)

`pigen_rtl_object_id` and `pigen_rtl_expr_id` are independent arena counters
(`include/pigen/rtl.h:168-205`). The assertion only ever passed on main because
valid/ready were `PIGEN_INVALID_ID` (UINT32_MAX), making the comparison trivially
true. It is a latent cross-arena index-collision defect in the frozen test.

In section 9's exact scenario (fresh model; the pre-call `pigen_lower_rtl_type`
publishes a type record but NO object and NO expression, so both the object and
expression arenas are empty before the declaration call), the correct
implementation publishes, per signal, one payload object then its two control
expressions. The first payload object is object index 0; the first control
expression (wire's valid) is expression index 0. The cross-arena comparison
`payload.index (0) != valid.index (0)` is therefore FALSE, and section 9 fails.

This collision is unavoidable for ANY correct implementation of the constant
controls:
- The payload object must be published (section 9's own shape assertions
  require it), and it is the first object in an empty object arena → index 0.
- A correct implementation must publish the descriptor constant controls
  (sections 10/11), and the first such expression lands in an empty expression
  arena → index 0.
- Object index 0 and expression index 0 are different records in different
  arenas, but the assertion compares their numeric `.index` fields, so they
  collide. No publication ordering, type choice, or memo behavior in
  `src/rtl_lower.c` can change this, because the two counters are independent
  and both provably start empty in this scenario.

The BOUNDARY section (8) does not have this defect: its `distinct` check compares
`valid.index != ready.index` (same expression arena), not a payload-vs-control
cross-arena comparison. Only section 9 does the cross-arena comparison.

## What is needed

A test-contract correction to `tests/rtl_lower_test.c` section 9 (`t6-net-variable-payload`):
replace the cross-arena `payload.index != valid.index` / `payload.index !=
ready.index` comparisons with a same-namespace distinctness witness — e.g. assert
the payload OBJECT and the control EXPRESSIONS are different record kinds
(`pigen_rtl_object_get(payload)->kind == PIGEN_RTL_OBJECT_VARIABLE` and
`pigen_rtl_expr_get(valid)->kind == PIGEN_RTL_EXPR_INTEGER`), or compare the two
payload objects against each other (same object arena) and the two controls
against each other (same expression arena). Keep the `wire payload != reg
payload` same-arena comparison. The implementation in this branch is complete and
correct; it will make the whole rtl-lower-test suite green once section 9's
cross-arena comparison is corrected to a same-namespace witness.
