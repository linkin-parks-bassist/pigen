## What now exists

The ordered output model now owns and manages each module's nested-layout
range; the caller no longer sets `layout` by hand.

`src/output.c` / `include/pigen/output.h`:

- `pigen_output_item_open(model, module)` appends a module item at top level
  and opens its nested scope. The module's range is owner-managed: it starts
  empty at the current end of the item array (`first = slot + 1, count = 0`)
  and is recorded both in `nested_layouts[module.index]` and in the module
  item's own `layout` field. Any caller-supplied `layout` is discarded.
- `pigen_output_item_add_child(model, module, item)` appends one item into
  that module's open scope and grows the range by one (`count += 1`), keeping
  the item's `layout` in lockstep. It finds the module's slot by scanning the
  item array for a matching MODULE identity (no third heap array is added).
- `pigen_output_item_layout(model, module)` reads the owner-managed range, or
  an empty `{0, 0}` for a module with no open scope or an invalid/missing slot.
- `nested_ensure` grows the parallel array keyed by the module's arena index
  and zeroes the grown tail (raw `realloc` does not), so sparse arena indices
  read back as an empty range rather than garbage.
- `pigen_free_output_model` is unchanged: it frees both arrays and zeroes the
  model. The builder stub still returns 0 with zero items; rtl-test is
  untouched.

`tests/output_test.c` gains one self-contained `t9-nesting` section (the
existing `t9-skeleton` section is unaltered) pinning: (a) top-level append of
an opaque item and an owner-opened module item; (b) two children appended into
the module scope record the range as exactly those children (`first = slot+1`,
`count = 2`, slots in order); (c) a no-child module reads back an empty range
even with another module populated; (d) the accessor returns empty for a
slot with no open scope and for a missing/invalid slot; (e) freeing zeroes
both arrays. `tests/contracts.json` gains exactly one entry covering
`src/output.c` + `src/source.c` + `src/util.c`, command
`make output-model-test T=t9-nesting`.

## Boundary report

- Interface exposed: `pigen_output_item_open`, `pigen_output_item_add_child`,
  `pigen_output_item_layout` (declared in include/pigen/output.h).
- Assumptions of neighbors: none; the model never validates structured
  identities against an RTL owner and takes no ownership of identity/span
  (value copy). A failed call returns `PIGEN_INVALID_ID` and may leave partial
  state; no test asserts what a failure left (how/should/compiler/builders/fail.md).
- No heap growth beyond the existing `items` and `nested_layouts` arrays; no
  new struct fields were added (the nesting state is derived from the two
  arrays).
- Excluded (later Task 9 steps, untouched): the monotonic-coverage gate,
  failed-nested-append count restoration, the syntax-tree build walk, and the
  missing-lowered-identity diagnostic.
