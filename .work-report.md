## Why it is blocked

The acceptance criterion cannot be met for the item as decomposed. The brief
states the helpers are "defined but not yet called by any section, so no
behavior changes and -Werror=unused-function does not fire." That premise is
false for this compiler and flag set:

- The Makefile's `CFLAGS` is `-std=c17 -Wall -Wextra -Wpedantic -Werror -O2`
  (Makefile:2). `-Werror` is mandatory; there is no `-Wno-unused` escape.
- GCC's `-Wunused-function` flags a `static` function that is not
  transitively reachable from a non-static (external) symbol.
  `rtest_shares_nonconst` is uncalled and is the sole top of the helper DAG,
  so it is flagged. `rtest_collect_exprs` is masked only because it is called
  by `rtest_shares_nonconst`.

Observed build:

```
cc -std=c17 -Wall -Wextra -Wpedantic -Werror -O2 -Iinclude -o /tmp/pigen-rtl-lower-test ...
tests/rtl_lower_test.c:70:12: error: 'rtest_shares_nonconst' defined but not used
   70 | static int rtest_shares_nonconst(const pigen_rtl_model *model,
cc1: all warnings being treated as errors
```

So "make rtl-lower-test compiles clean under -Werror and the full run stays
green (16 passed / 0 failed)" is impossible with the helpers present and
uncalled. I confirmed there is no `__attribute__((unused))` suppression
anywhere in the file's history (de0f62f, 07b7775: zero occurrences).

The proven-compiling form exists: sibling commit `07b7775`
("Re-add the Task 8 (1) FIRE IDENTITY family as its own hidden test packet")
re-adds these SAME byte-identical helpers together with the fire-identity
family section that CALLS them. The helpers only build clean once their
calling section is present. That commit is on a separate branch and is not an
ancestor of my HEAD, so it is not available to this item.

I reverted the working tree to a clean state (baseline `make rtl-lower-test`
is 16 passed / 0 failed) rather than leave a broken partial.
